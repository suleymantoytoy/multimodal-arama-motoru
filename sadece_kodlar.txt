# ============================================================
# Bu dosya, FastAPI servisimizi (api/main.py) bir Docker container'i
# icine paketlemek icin "tarif" (recipe) gorevi gorur. Docker, bu
# dosyayi okuyup adim adim bir "image" (imaj) olusturur - image,
# calisan bir programin ve TUM bagimliliklarinin (Python, kutuphaneler,
# kodun kendisi) tek bir pakette dondurulmus hali gibi dusunulebilir.
# ============================================================

# FROM: hangi TEMEL imajdan baslayacagimizi belirtir. python:3.11-slim,
# icinde Python 3.11 kurulu, gereksiz eklentilerden arindirilmis
# (slim) kucuk bir Linux imaji - boylece kendi Python'umuzu sifirdan
# kurmamiza gerek kalmiyor.
FROM python:3.11-slim

# WORKDIR: container'in ICINDE calisacagimiz klasoru belirler - tipki
# terminalde "cd /app" yapmak gibi. Bundan sonraki tum komutlar bu
# klasorun icinde calisir.
WORKDIR /app

# COPY: bilgisayarindaki (host) dosyalari container'in ICINE kopyalar.
# Once SADECE requirements.txt'i kopyaliyoruz (henuz butun kodu degil) -
# bu, Docker'in "katman onbellegi" (layer caching) mantigindan
# faydalanmak icin bir optimizasyon: eger sadece KODUNU degistirirsen
# (requirements.txt'i degil), Docker bu adimi TEKRAR calistirmaz,
# onceki calistirmadan kalan sonucu kullanir - bu, image'i yeniden
# olustururken zamandan tasarruf sağlar.
COPY requirements.txt .

# RUN: container'in ICINDE bir komut calistirir - burada pip ile
# tum bagimliliklari kuruyoruz. --no-cache-dir: pip'in kendi
# onbellegini TUTMAMASINI sagliyoruz, boylece image'in boyutu
# gereksiz yere buyumez.
RUN pip install --no-cache-dir -r requirements.txt

# Simdi PROJENIN TAMAMINI kopyaliyoruz (kod, veri, index dosyalari vb.)
COPY . .

# EXPOSE: bu container'in HANGI PORTTAN disariya konustugunu
# BELGELIYOR (dokumantasyon amacli, gercek port acmayi asagida
# docker-compose.yml yapacak).
EXPOSE 8000

# CMD: container BASLATILDIGINDA calistirilacak KOMUT. --host 0.0.0.0
# ONEMLI: bu, API'nin SADECE container'in kendi icinden degil,
# DISARIDAN da (senin bilgisayarindan, tarayicidan) erisilebilir
# olmasini sagliyor - "127.0.0.1" yerine "0.0.0.0" kullanmak,
# container ortamlarinda STANDART bir gerekliliktir.
CMD ["uvicorn", "api.main:app", "--host", "0.0.0.0", "--port", "8000"]

# Multi-Modal Semantic Search Engine

A hybrid image search system that combines semantic understanding (CLIP embeddings), classical keyword matching (BM25), and a three-tier fallback architecture: search a local dataset first, fall back to a live web image source, and finally generate a new image with AI when nothing relevant exists anywhere else.

## What It Does

Type a query like `"a dog"` or `"a dog walking on the moon"`, or upload an image, and the system:

1. **Searches locally** — runs the query through CLIP and BM25 over a 5,000-image dataset (COCO val2017), fuses both rankings with Reciprocal Rank Fusion (RRF), and returns results if the best match is confident enough.
2. **Falls back to the web** — if the local match is too weak, it queries the Unsplash API for real photographs, then re-scores the top result with the same CLIP model to confirm it's actually relevant (not just a keyword coincidence).
3. **Generates an image** — if neither source has anything relevant, an LLM (Groq, running Llama 3 / GPT-OSS) rewrites the query into a detailed image-generation prompt, and a diffusion model (FLUX.1-schnell, with a local fallback) generates a new image on the spot.

Every result is labeled with its source — local, web, or AI-generated — so the user always knows what they're looking at.


## Architecture

```mermaid
flowchart TD
    A[User query: text or image] --> B{Local hybrid search<br/>CLIP + BM25 + RRF}
    B -->|score >= threshold| C[Return local results]
    B -->|score < threshold| D{Unsplash search}
    D -->|found + re-scored by CLIP<br/>score >= threshold| E[Return web results]
    D -->|empty or re-scored score too low| F[Prompt engineering<br/>Groq API]
    F --> G[Image generation<br/>FLUX.1-schnell -> sd-turbo fallback]
    G --> H[Return AI-generated image]
```


## Tech Stack

| Layer | Technology |
|---|---|
| Embedding model | OpenCLIP (ViT-B/32) |
| Image captioning | BLIP (Salesforce/blip-image-captioning-base) |
| Vector search | FAISS (Flat / IVF / HNSW, benchmarked) |
| Keyword search | rank-bm25 |
| Result fusion | Reciprocal Rank Fusion (RRF) |
| Web fallback | Unsplash API |
| Prompt engineering | Groq API (cloud, OpenAI-compatible) |
| Image generation | FLUX.1-schnell (Hugging Face), sd-turbo (local fallback) |
| Backend | FastAPI |
| Frontend | Streamlit |


## Running Locally

```bash
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Create a `.env` file in the project root:
```
UNSPLASH_ACCESS_KEY=your_key_here
HF_TOKEN=your_token_here
GROQ_API_KEY=your_key_here
```

Start the API (in one terminal):
```bash
uvicorn api.main:app --reload
```

Start the UI (in a second terminal):
```bash
streamlit run ui/app.py
```

Open `http://localhost:8501` in your browser.

## API Endpoints

- `GET /health` — service health check
- `POST /search/text` — `{"sorgu": "a dog", "k": 5}` → hybrid search across all three tiers
- `POST /search/image` — upload an image, get visually similar results (also falls back through the web/generation tiers if the local match is weak)

Interactive API docs available at `http://localhost:8000/docs` while the API is running.

## Evaluation

The retrieval quality of the local layer was measured on a 50-query test set (derived from BLIP captions, seed=42 for reproducibility) using standard information retrieval metrics.

| Approach | Precision@5 | Recall@5 | MRR |
|---|---|---|---|
| CLIP only | 0.1000 | 0.5000 | 0.3680 |
| BM25 only | 0.1880 | 0.9400 | 0.8783 |
| Hybrid (RRF) | 0.1640 | 0.8200 | 0.6213 |

**Note on BM25's high score:** the test queries were built from the *full* BLIP caption of each image, which gives BM25 an artificial advantage (near-exact keyword matches). This does not reflect real-world usage, where queries are short and imprecise — under those conditions, **Note on the first table:** its queries were built from BLIP captions, the same text BM25 indexes, which gave BM25 an artificial advantage. To remove that bias, two additional test sets were built from COCO's human-written annotations (independent of BLIP):

| Approach | Precision@5 (77 category queries) | Recall@5 (200 human captions) | MRR@5 (200 human captions) |
|---|---|---|---|
| CLIP only | 0.873 | 0.655 | 0.523 |
| BM25 only | 0.852 | 0.210 | 0.113 |
| Hybrid (RRF) | 0.904 | 0.575 | 0.380 |

Random selection would score Precision@5 = 0.031. Paired bootstrap (10,000 resamples, 95% intervals) shows that hybrid beats BM25 clearly on human captions, is statistically indistinguishable from CLIP on short category queries, and is **worse than CLIP alone on human-written captions**. The hybrid's advantage is therefore not established by these measurements. Details: `docs/karar_gunlugu.md`.. Full analysis in `docs/eval_raporu.md`.

Vector index types (Flat, IVF, HNSW) were also benchmarked for speed/accuracy trade-off — HNSW was selected as the production default (~8x faster than brute-force Flat search with ~95-97% result overlap). Full numbers in `docs/karar_gunlugu.md`.

## Known Limitations

- **Docker:** `Dockerfile.api`, `Dockerfile.ui`, and `docker-compose.yml` are included and the architecture was verified working in earlier builds (both services started, communicated, and served requests correctly). However, this development environment (Windows + third-party antivirus + Docker Desktop) hit a series of unrelated infrastructure issues that could not be fully resolved without disproportionate time investment. The system is therefore demonstrated running locally via `uvicorn` + `streamlit` rather than via `docker-compose up`.
- **Reverse image search:** the system does not find real, existing images of a specific character or subject across the web (like Google Images' "search by image"). It performs semantic similarity search and AI generation, not web-scale visual entity matching — that would require a separate paid API (Google Cloud Vision, Bing Visual Search, TinEye).
- **CLIP's known weaknesses:** occasional confusion between texture and subject (e.g. fur patterns vs. animals), and lower confidence on abstract or highly compositional queries. Documented with examples in `docs/karar_gunlugu.md`.

# ============================================================
# Bu dosya, projenin FastAPI servisini olusturur. Su ana kadar
# yazdigimiz tum arama mantigini (akilli_ara: yerel -> harici ->
# uretim) bir HTTP API'sinin arkasina koyuyoruz - boylece Streamlit
# arayuzu, Docker container'i veya baska herhangi bir istemci
# (mobil uygulama dahil) bu API'ye istek atarak arama yapabilir.
#
# FASTAPI NEDIR? Python'da hizli, modern bir web API framework'u.
# Fonksiyonlarimizin ustune "decorator" (@app.post gibi) ekleyerek,
# onlari otomatik olarak HTTP endpoint'lerine ceviriyor - ayrica
# kendiliginden bir test arayuzu (Swagger, /docs adresinde) uretiyor.
# ============================================================

import sys
import os

# search klasorundeki akilli_ara() fonksiyonunu import edebilmek
# icin, o klasoru Python'un arama yoluna ekliyoruz.
sys.path.append(os.path.join(os.path.dirname(__file__), "..", "search"))

from fastapi import FastAPI, UploadFile, File, HTTPException
from pydantic import BaseModel
from typing import Optional

# FastAPI uygulamasini olusturuyoruz - title/description, Swagger
# arayuzunda (/docs) gorunecek basliktir.
app = FastAPI(
    title="Multi-Modal Semantik Arama API",
    description="Metin veya gorsel ile CLIP+BM25+RRF hibrit arama, "
                 "yerelde bulunamazsa Unsplash'e, o da bulamazsa "
                 "AI goersel uretimine duser.",
)


# ------------------------------------------------------------
# Pydantic MODELI: FastAPI, bir istegin GOVDESININ (body) nasil
# gorunmesi gerektigini bilmek icin boyle bir "sema" (schema) sinifi
# ister. Kullanici /search/text endpoint'ine istek atarken, govdede
# {"sorgu": "...", "k": 10} seklinde bir JSON gondermesi gerekecek -
# bu sinif, o JSON'un YAPISINI tanimliyor. FastAPI, gelen veriyi
# OTOMATIK olarak bu sinifin kurallarina gore DOGRULAR (orn. "sorgu"
# eksikse, otomatik olarak anlamli bir hata doner - bizim elle
# kontrol etmemize gerek kalmaz).
# ------------------------------------------------------------
class MetinSorgusu(BaseModel):
    sorgu: str
    k: Optional[int] = 10  # k belirtilmezse varsayilan 10 kullanilir


# ------------------------------------------------------------
# Bu degiskenler, "akilli_ara" fonksiyonunu SADECE ILK ISTEKTE
# import edip, sonrasinda tekrar tekrar KULLANMAK icin var. Boyle
# yapmazsak, her istek geldiginde CLIP/BLIP modellerini yeniden
# yuklemeye calisirdik - bu ÇOK YAVAS olurdu. "Lazy loading"
# (tembel yukleme) denen bu yontem, ilk istegi biraz yavaslatir
# ama sonraki TUM istekleri hizlandirir.
# ------------------------------------------------------------
_akilli_ara = None


def _arama_fonksiyonunu_yukle():
    """
    hybrid_search modulundeki akilli_ara fonksiyonunu, SADECE
    ilk cagrildiginda import eder ve bir daha import etmez -
    boylece FastAPI baslatilirken degil, ILK ARAMA ISTEGI
    geldiginde modeller yuklenir (bu, API'nin baslatma suresini
    kisaltir, ama ilk arama biraz gecikmeli olur - kabul edilebilir
    bir trade-off).
    """
    global _akilli_ara
    if _akilli_ara is None:
        from hybrid_search import akilli_ara
        _akilli_ara = akilli_ara
    return _akilli_ara


# ------------------------------------------------------------
# ENDPOINT 1: Saglik kontrolu (health check)
# Bu, "API ayakta mi, calisiyor mu" diye kontrol etmek icin
# kullanilan STANDART bir endpoint - gercek sistemlerde (Docker,
# Kubernetes gibi ortamlarda) servisin hayatta olup olmadigini
# otomatik kontrol etmek icin kullanilir.
# ------------------------------------------------------------
@app.get("/health")
def saglik_kontrolu():
    return {"durum": "calisiyor"}


# ------------------------------------------------------------
# ENDPOINT 2: Metin ile arama
# POST istegi kullaniyoruz (GET degil) cunku istemci bize bir
# "govde" (body - sorgu metni gibi) gonderiyor; GET istekleri
# genelde govde tasimaz, sadece URL parametreleri tasir.
# ------------------------------------------------------------
@app.post("/search/text")
def metin_ile_ara(istek: MetinSorgusu):
    """
    istek: MetinSorgusu sinifina uygun bir JSON govdesi
    (orn. {"sorgu": "a dog", "k": 5}) - FastAPI bunu OTOMATIK
    olarak Python objesine cevirir, biz dogrudan istek.sorgu
    seklinde erisebiliriz.
    """
    akilli_ara = _arama_fonksiyonunu_yukle()

    try:
        sonuc = akilli_ara(istek.sorgu, k=istek.k)
        return sonuc
    except Exception as hata:
        # HTTPException: FastAPI'ye ozel bir hata turu - bu,
        # istemciye DUZGUN bir HTTP hata kodu (500 = sunucu hatasi)
        # ve anlamli bir mesajla cevap donmemizi saglar, ham bir
        # Python hatasi/traceback GORUNMEZ istemciye.
        raise HTTPException(status_code=500, detail=f"Arama sirasinda hata: {hata}")


# ------------------------------------------------------------
# ENDPOINT 3: Gorsel ile arama
# Burada govde JSON degil, bir DOSYA YUKLEMESI (multipart/form-data)
# - bu yuzden Pydantic modeli yerine FastAPI'nin UploadFile turunu
# kullaniyoruz.
# ------------------------------------------------------------
@app.post("/search/image")
async def gorsel_ile_ara(dosya: UploadFile = File(...), k: int = 10, esik: float = 0.75):
    # NOT: Gorsel-gorsel CLIP karsilastirmalari, metin-gorsel
    # karsilastirmalardan DOGAL OLARAK daha yuksek skorlar uretir -
    # CLIP, iki gorsel arasinda renk/kompozisyon gibi yuzeysel
    # ozellikleri bile "benzerlik" olarak sayabiliyor. Bu yuzden
    # metin aramasinda kullandigimiz esik (0.25) burada COK DUSUK
    # kaliyor - test edildi: alakasiz bir anime karakteri ile COCO
    # veri setindeki bir vazo gorseli arasinda bile 0.57 gibi
    # YANILTICI YUKSEK bir skor cikti. 0.75, ilk kalibrasyon olarak
    # kondu - daha fazla ornekle test edilip ayarlanabilir.
    """
    ONCEKI VERSIYONDAN FARKI: Artik skor kontrolu yapiyor. Yuklenen
    gorsel, yerel veri setimizle (COCO - gercek fotograflar) YETERINCE
    benzemiyorsa (orn. bir anime/cizim karakteri yuklendiyse), sonuc
    ALAKASIZ olabiliyordu. Simdi:
      1. Once yerelde ara, EN IYI skoru kontrol et.
      2. Skor esigin USTUNDEYSE: yerel sonuclari dondur (eskisi gibi).
      3. Skor esigin ALTINDAYSA: BLIP ile yuklenen gorseli TARIF ET
         (bir caption uret), sonra bu caption'i akilli_ara()'ya
         gonder - bu da otomatik olarak harici (Unsplash) veya
         uretim (AI) katmanlarina duser, tipki metin aramasinda
         oldugu gibi.
    """
    sys.path.append(os.path.join(os.path.dirname(__file__), "..", "embeddings"))
    from clip_encoder import encode_image
    from hybrid_search import _hnsw_index, _clip_dosya_yollari, akilli_ara

    try:
        gecici_yol = f"./_gecici_{dosya.filename}"
        icerik = await dosya.read()
        with open(gecici_yol, "wb") as f:
            f.write(icerik)

        sorgu_vektoru = encode_image(gecici_yol).reshape(1, -1).astype("float32")

        # D: benzerlik skorlari, I: index numaralari
        D, I = _hnsw_index.search(sorgu_vektoru, k)
        en_iyi_skor = float(D[0][0])

        if en_iyi_skor >= esik:
            # Yerelde YETERINCE benzer bir sey var - eskisi gibi devam.
            sonuclar = [_clip_dosya_yollari[i] for i in I[0]]
            os.remove(gecici_yol)
            return {
                "kaynak": "yerel_gorsel_arama",
                "en_iyi_skor": en_iyi_skor,
                "sonuclar": sonuclar,
            }

        # Yerelde YETERSIZ - BLIP ile gorseli TARIF EDIP, o tarifi
        # akilli_ara()'ya (metin tabanli uc katmanli zincire) gonderiyoruz.
        print(f"[search/image] Yerel skor dusuk ({en_iyi_skor:.4f}) - BLIP ile gorsel tarif ediliyor...")
        from caption_generator import generate_caption
        uretilen_caption = generate_caption(gecici_yol)
        os.remove(gecici_yol)

        print(f"[search/image] Uretilen tarif: '{uretilen_caption}' - akilli_ara()'ya yonlendiriliyor...")
        sonuc = akilli_ara(uretilen_caption, k=k, esik=esik)
        # Kullanicinin, bu aramanin ASLINDA gorselden turetilmis bir
        # metin sorgusuyla yapildigini bilmesi icin, uretilen caption'i
        # da sonuca ekliyoruz.
        sonuc["gorselden_uretilen_tarif"] = uretilen_caption
        return sonuc

    except Exception as hata:
        raise HTTPException(status_code=500, detail=f"Gorsel arama sirasinda hata: {hata}")

# Değerlendirme Raporu (Faz 4)

Bu rapor, 50 sorguluk rastgele seçilmiş bir test seti üzerinde `Sadece CLIP`, `Sadece BM25` ve `Hibrit (RRF)` yaklaşımlarının performansını değerlendirmektedir. Faz 6'da, BLIP'ten bağımsız iki ek test setiyle yapılan genişletilmiş değerlendirme aynı dosyanın ikinci yarısında yer alır.

Test seti: `eval/test_sorgular.json` (BLIP caption'larından, seed=42 ile rastgele seçilmiş 50 sorgu-görsel çifti).
Metrikler: `eval/evaluate.py` (precision@k, recall@k, MRR - elle yazılmış, standart bilgi getirimi formülleri).

## Sayısal Sonuçlar (k=5)

| Yaklaşım | Precision@5 | Recall@5 | MRR |
| :--- | :--- | :--- | :--- |
| Sadece CLIP | 0.1000 | 0.5000 | 0.3680 |
| Sadece BM25 | 0.1880 | 0.9400 | 0.8783 |
| Hibrit (RRF) | 0.1640 | 0.8200 | 0.6213 |

Not: Her sorgunun tek bir doğru cevabı olduğu için Precision@5 teorik olarak en fazla 0.20 olabilir (5 sonuçtan en çok 1'i doğru). Bu tablodaki Precision değerleri bu tavana göre okunmalıdır.

## Analiz ve Beklenmeyen Sonuçların Gerekçesi

Tabloya bakıldığında BM25 modelinin hem CLIP'i hem de Hibrit yaklaşımı belirgin bir farkla geçtiği görülmektedir. Hibrit yaklaşımın en iyi sonucu vermesi beklenirken geride kalmasının nedeni, **test setinin oluşturulma metodolojisidir.**

* **BM25'in Suni Başarısı:** `build_test_set.py` dosyasında, her bir test görseli için BLIP tarafından üretilen caption'ların *tamamı* hiçbir kısaltma yapılmadan doğrudan arama sorgusu olarak kullanılmıştır. BM25 bir kelime eşleştirme algoritması olduğu için, indekslediği metnin birebir aynısı aratıldığında mükemmele yakın (~%94 Recall) bir eşleşme bulmuştur. Bu, gerçek kullanıcı davranışını yansıtmayan, teste özgü bir avantajdır.
* **CLIP'in Gerçek Performansı:** CLIP modeli, metin ile metni değil; metin ile görseli eşleştirmektedir. Kelime kopyası çekme şansı olmamasına rağmen, anlamsal uzayda ilk 5 sonuç içinde doğru görseli %50 oranında bulabilmesi, modelin multimodel anlama yeteneğinin güçlü olduğunu kanıtlamaktadır.
* **Hibrit (RRF) Durumu:** Hibrit model, BM25'in "mükemmel" listesi ile CLIP'in anlamsal listesini birleştirdiği için, BM25'in metin eşleştirmesindeki suni avantajını bir miktar törpülemiş ve iki metrik arasında bir dengeye (0.62 MRR) oturmuştur.

**Not (Faz 6 ile güncellendi):** Bu bölümün ilk halinde, gerçek kullanımda (kısa, spesifik olmayan veya hatalı sorgularda) BM25'in başarısının düşeceği ve CLIP ile Hibrit yaklaşımın öne çıkacağı öngörülmüştü. BLIP'ten bağımsız setlerle yapılan ek değerlendirme (aşağıda) bu öngörüyü **yalnızca yarısıyla** doğruladı: BM25'in başarısı gerçekten çöktü ve hem CLIP hem Hibrit onu geçti, ancak Hibrit, CLIP'i geçemedi.

## Ek Değerlendirme: BLIP'ten Bağımsız Test Setleri (Faz 6)

### Neden gerekti?

İlk değerlendirmedeki 50 sorgu BLIP caption'larından, BM25 indeksi de aynı caption'lardan kuruluydu: BM25 fiilen kendi metnini arıyordu. Bu bölüm, COCO'nun insan yazımı anotasyonlarıyla (BLIP'ten bağımsız) kurulan iki ek test setinin sonuçlarını ve bunların istatistiksel analizini içerir. Görsel ID eşleşmesi önce ölçüldü: 5.000 görselin tamamı iki anotasyon dosyasıyla da eşleşti.

### Test setleri

1. **Kategori seti (77 sorgu):** "dog", "pizza" gibi kısa kategori adları. Doğru cevap: o kategoriyi içeren tüm görseller. "person" (görsellerin %54'ünde var, ölçüm anlamsız kalır) ve 20'den az görselli kategoriler (toaster, hair drier) dışarıda. Rastgele seçimle beklenen Precision@5 = 0.031.
2. **İnsan caption seti (200 sorgu):** 200 rastgele görselin her birinin 5 insan caption'ından biri sorgu. Doğru cevap: kaynak görsel (tek hedef). Tek hedefli sette Recall@5, "ilk 5'te bulma oranı" demektir.
3. **Dev seti (500 sorgu):** Ağırlıklı RRF denemesinde ağırlık seçimi için, test setindeki görsellerin DIŞINDAN seçildi (seed=7).

Tüm sorgularda k=5; bu yüzden MRR de MRR@5'tir (ilk doğru cevap 5. sıradan aşağıdaysa 0).

### Sonuçlar

| Yaklaşım | P@5 (kategori) | Recall@5 (caption) | MRR@5 (caption) |
| :--- | :--- | :--- | :--- |
| CLIP | 0.8727 ± 0.0276 | 0.6550 ± 0.0337 | 0.5226 ± 0.0318 |
| BM25 | 0.8519 ± 0.0290 | 0.2100 ± 0.0289 | 0.1127 ± 0.0190 |
| Hibrit (RRF) | 0.9039 ± 0.0205 | 0.5750 ± 0.0350 | 0.3798 ± 0.0289 |

(± standart hata.) Karşılaştırma için, ilk (BLIP tabanlı) setteki BM25 MRR'ı 0.8783'tü; BLIP'ten bağımsız sorgularda 0.1127'ye düştü. Yukarıdaki "BM25 yapay şekilde yüksek" analizi bu sayıyla doğrulandı.

### İstatistiksel karşılaştırma (eşlemeli bootstrap)

10.000 tekrar, seed=42, sorgular yerine koyarak yeniden çekildi, %95 güven aralığı.

| Metrik | Karşılaştırma | Ort. fark | %95 aralık | Sonuç |
| :--- | :--- | :--- | :--- | :--- |
| P@5 (kategori) | Hibrit − CLIP | +0.0312 | [−0.0052, +0.0675] | Ayırt edilemiyor |
| P@5 (kategori) | Hibrit − BM25 | +0.0519 | [+0.0078, +0.0961] | Sınırda* |
| Recall@5 (caption) | Hibrit − CLIP | −0.0800 | [−0.1350, −0.0300] | Hibrit daha kötü |
| Recall@5 (caption) | Hibrit − BM25 | +0.3650 | [+0.2900, +0.4400] | Hibrit daha iyi |
| MRR@5 (caption) | Hibrit − CLIP | −0.1428 | [−0.1907, −0.0945] | Hibrit daha kötü |
| MRR@5 (caption) | Hibrit − BM25 | +0.2671 | [+0.2160, +0.3195] | Hibrit daha iyi |

\* Alt sınır 0'a çok yakın. Altı karşılaştırma yapıldığı için yaklaşık bir çoklu-karşılaştırma düzeltmesiyle aralık 0'ı içerir; bu sonuç "kesin" olarak raporlanmaz (düzeltme yaklaşıktır, tam Bonferroni değildir).

### Ağırlıklı RRF denemesi

BM25'e düşük ağırlık verilirse hibrit CLIP'e yetişir mi? Tasarım sonuçlar görülmeden sabitlendi: ağırlık sadece dev setinde seçildi, test setlerinde bir kez ölçüldü. CLIP ağırlığı 1.0'da sabit, BM25 ağırlığı {0, 0.1, 0.2, 0.3, 0.5, 0.75, 1.0}; RRF k=60 ve aday havuzu (20) sabit.

| BM25 ağırlığı | Dev Recall@5 | Dev MRR@5 |
| :--- | :--- | :--- |
| 0.0 | 0.6600 | 0.4950 |
| 0.1 | 0.6500 | 0.4595 |
| 0.2 | 0.6220 | 0.4184 |
| 0.3 | 0.6020 | 0.4002 |
| 0.5 | 0.6020 | 0.3959 |
| 0.75 | 0.6000 | 0.3900 |
| 1.0 | 0.5560 | 0.3679 |

Eğri neredeyse tek yönlü düşüyor; seçilen ağırlık 0.0 (saf CLIP). Komşu ağırlıklar arasındaki tek tek farklar standart hata içinde, güvenilir olan eğrinin genel yönü. Test sonuçları önceki değerlerle birebir tutarlı (seçilen ağırlık CLIP ile aynı olduğu için "seçilen − eşit" karşılaştırması önceki bootstrap'in işaret çevrilmiş aynısıdır, yeni kanıt sayılmaz; bağımsız doğrulama dev setidir).

### Tamamlayıcılık analizi

Soru: BM25, CLIP'in kaçırdığını hiç yakalıyor mu? (İnsan caption sorguları, tek hedef.)

| Ölçüm | Dev (500) | Test (200) |
| :--- | :--- | :--- |
| CLIP ilk 5'te buldu | %66.0 | %65.5 |
| BM25 ilk 5'te buldu | %21.0 | %21.0 |
| Sadece CLIP buldu (ilk 5) | 233 | 99 |
| Sadece BM25 buldu (ilk 5) | 8 | 10 |
| BM25 ilk 20'de buldu, CLIP ilk 20'de bulamadı | 12 (%2.4) | 9 (%4.5) |
| Hibrit ilk 5'te buldu | %55.6 | %57.5 |

Hibrit, "sadece CLIP buldu" sorgulardan dev'de 69/233, test'te 23/99 tanesini kaybetti; "sadece BM25 buldu" sorgulardan dev'de 5/8, test'te 4/10 tanesini kurtardı.

### Sonuç

- Cümle tarzı insan sorgularında, BLIP caption'ları üzerinde kurulan BM25 ile yapılan eşit ağırlıklı hibrit, CLIP'ten **daha kötü** (Recall ve MRR farkları güven aralıklarıyla destekleniyor) ve düşük ağırlıkla kurtarılamadı.
- Kısa kategori sorgularında hibrit-CLIP farkı **ayırt edilemiyor**; hibritin üstünlüğü iddia edilemez.
- Hibrit her durumda BM25'ten iyi; BM25 tek başına insan sorgularında zayıf.
- BM25, CLIP'in ilk 20'de bulamadığı hedefleri nadiren yakalıyor; yani bu sorgu türünde yeni bilgi eklemiyor.
- İlk analizde yazılan beklenti ("kısa, eksik kelimeli sorgularda CLIP ve hibrit öne çıkar") **yalnızca yarısıyla doğru çıktı**: ikisi de BM25'i geçiyor, ama hibrit CLIP'i geçemiyor.

### Sınırlar (açıkça belirtilmeli)

- İnsan caption setinde tek doğru cevap var; aynı sahneyi gösteren başka bir görsel "yanlış" sayılır, bu mutlak skorları aşağı çeker (yöntemlerin göreli kıyasını etkilemez).
- Kategori setinde doğru cevaplar COCO anotasyonlarından geliyor; kategori anotasyonu eksik (örneğin küçük/arka plan nesne) görseller "yanlış" sayılır, Precision'ı aşağı çeker.
- Ağırlık yalnızca insan-caption sorgularında seçildi; kategori için ayrı bir dev seti yok. Yalnızca BM25 ağırlığı arandı.
- BM25'in zayıf olmasının NEDENİ (BLIP caption'larının kısa ve jenerik olması) bir hipotezdir, **ölçülmedi**.
- Altı istatistiksel karşılaştırma yapıldı; sınıra yakın sonuçlar düzeltme sonrası anlamsızlaşabilir.
- Üretim kodu (`hibrit_ara`) değiştirilmedi. Karar: hibrit mimari korunuyor, bulgu bir ablation sonucu olarak belgeleniyor; olası iyileştirme yönü BM25 metin kaynağının (örneğin daha zengin caption'lar) geliştirilmesi. COCO etiketlerini BM25 metnine eklemek kategori test setiyle sızıntı yaratacağı için tercih edilmez.

## Not: Değerlendirme Kapsamı

Bu rapordaki değerlendirmeler SADECE yerel katman (CLIP + BM25 + RRF) üzerinde yapılmıştır. Faz 3.5 (harici Unsplash arama) ve Faz 3.75 (AI görsel üretim) katmanları bu değerlendirmelerin kapsamı dışındadır - onlar "yerelde yoksa ne olur" sorusuna ayrı bir cevaptır, ana değerlendirme metodolojisini değiştirmez (bkz. `guncelleme_kaydi.pdf`, Bölüm 3).

## Faz 2 - Duzeltme: Genisletilmis Benchmark (25 sorgu, 5 tekrar)

Ilk benchmark sadece 10 sorgu ve tek olcumle yapilmisti - istatistiksel
guven artirmak icin 25 sorguya cikarildi, her sorgu 5 kez tekrarlanip
ortalamasi alindi.

| Index | Ort. Sure (ms) | Flat ile Ortusme |
|-------|---------------|-------------------|
| Flat  | 0.816         | %100 (referans)   |
| IVF   | 0.004         | %68.8             |
| HNSW  | 0.052         | %94.8             |

Sonuc onceki (kucuk olcekli) benchmark ile TUTARLI cikti - HNSW
karari degismedi, hala en iyi hiz/dogruluk dengesini veriyor.
Bu, ilk benchmark'in tesadufen "sansli" bir sonuc olmadigini,
gercekten guvenilir oldugunu gosteriyor.

| Index | Ort. Sure (ms) | Flat ile Ortusme |
|-------|---------------|-------------------|
| Flat  | 0.79          | %100 (referans)   |
| IVF   | 0.24          | %65               |
| HNSW  | 0.10          | %97               |

**Karar: HNSW, production/varsayilan index olarak secildi.**
Gerekce: Flat'e gore ~8x daha hizli, dogruluk kaybi ihmal edilebilir
duzeyde (%97 ortusme). IVF'nin dusuk ortusme orani (%65), varsayilan
nprobe=1 ayarindan kaynaklaniyor - nprobe artirilarak iyilestirilebilir
ama bu ekstra bir parametre ayari gerektirir, HNSW ekstra ayar
gerektirmeden zaten iyi sonuc verdigi icin HNSW tercih edildi.

Not: 5.000 gorsel gibi kucuk-orta bir olcekte Flat bile pratikte
"yavas" sayilmaz (0.79ms) - asil fark cok daha buyuk veri setlerinde
(orn. 1 milyon+ gorsel) ortaya cikar. Bu projede HNSW'yi secmemizin
nedeni "zorunluluk" degil, "doğru mühendislik pratiği" - gercek
sistemlerde boyle secilir.

## Faz 3.75 - Prompt Zenginlestirme ve Gorsel Uretim Katmani

### Prompt Zenginlestirme (LLM Katmani)

Ilk denemede flan-t5-small (kucuk, yerel bir Hugging Face modeli,
transformers uzerinden) kullanildi. Sonuc yetersizdi - model girdiyi
ANLAMSIZCA TEKRARLIYORDU ("a dog walking on the moon is a dog
walking on the moon" gibi), gercek bir zenginlestirme yapmiyordu.
Bu denemeden vazgecildi.

Yerine Ollama (yerel calisan, ucretsiz, API anahtari gerektirmeyen
bir LLM sunucusu, localhost:11434) ile llama3.1:latest modeli
kullanilmaya baslandi. Sonuc kalitesi cok daha iyi - isiklandirma,
kompozisyon, atmosfer detaylari iceren gercek prompt engineering
ciktisi.

Karsilasilan ve cozulen sorunlar:
- Ilk cagrida model bellege yuklenirken (~4.9 GB) gecikme oluyordu,
  30 saniyelik timeout yetersiz kaliyordu -> 120 saniyeye cikarildi.
- Ollama'nin urettigi zengin promptlar (150+ kelime) Stable
  Diffusion'in metin kodlayicisi CLIP'in 77 token sinirini asiyordu,
  promptun sonu sessizce kesiliyordu (log'da "truncated" uyarisi
  goruldu) -> Ollama'ya verilen talimata "60 kelimenin altinda kal"
  kisiti eklendi, sorun cozuldu.

### Gorsel Uretim Katmani

Ilk denemede stabilityai/sd-turbo (yerel, diffusers uzerinden,
damitilmis/distilled bir model) kullanildi. Hizli (CPU'da 4 adimda
~20 saniye) ama ciddi bir kalite sorunu ortaya cikti: "compositional
binding" zayifligi - model, guclu cagrisimli kelimeleri (orn.
"spacesuit") baskin ogeye (orn. "dog") tercih ediyor, tamamen alakasiz
bir sonuc (bir insan/astronot figuru) uretebiliyor. Test: "a dog
walking on the moon" + "spacesuit" iceren zenginlestirilmis prompt
-> tamamen bir astronot gorseli cikti, kopek yoktu. "Spacesuit"
kelimesi kaldirilinca ("dog on moon surface with craters/stars")
sonuc kabul edilebilir kaliteye dondu - yani sorun modelin genel
kopek algisi degil, ozellikle guclu insan cagrisimi yapan kelimelerle
kompozisyon kurma zayifligiydi.

Karar: sd-turbo, damitilmis oldugu icin bu zayifligi adim sayisini
artirarak (num_inference_steps) tam cozemiyor - damitma, modelin
ince kompozisyon becerisini hiz icin feda etmesi anlamina geliyor.
Bu yuzden yerel/damitilmis modelden vazgecilip Hugging Face
Inference API uzerinden FLUX.1-schnell modeline gecildi:
- Tam adimli, damitilmamis, kompozisyon/prompt sadakati konusunda
  bilinen sekilde daha guclu bir model.
- CPU yukumuz yok (bulutta calisiyor), hizli donuyor.
- Ucretsiz katman var, ama bir Hugging Face hesabi + API token
  (HF_TOKEN) gerektiriyor - "API anahtari gerektirmez" hedefinden
  kucuk bir sapma, ama para gerektirmiyor, sadece ucretsiz kayit.
- HF_TOKEN, .env dosyasina eklendi, python-dotenv ile okunuyor -
  projenin Unsplash API anahtarinda kullandigi yontemle tutarli.

Ders: Ucretsiz/yerel/hizli secimlerin (sd-turbo) bir bedeli oldugunu
gozlemledik - bu bedel bazen "hicbir zaman calismaz" degil, "bazi
spesifik durumlarda sessizce yanlis sonuc verir" seklinde ortaya
cikiyor (compositional binding). Boyle durumlarda sonucu saklamadan
raporlamak ve daha guclu bir alternatife gecmek, "gunu kurtarmaktan"
daha onemli - bu proje boyunca benimsedigimiz ilkeyle (Faz 4'teki
"sonuc kotu ciksa da saklama" prensibi) tutarli bir karar.

|---|---|---|---|
| CLIP | 0.8727 +/- 0.0276 | 0.6550 +/- 0.0337 | 0.5226 +/- 0.0318 |
| BM25 | 0.8519 +/- 0.0290 | 0.2100 +/- 0.0289 | 0.1127 +/- 0.0190 |
| Hibrit (RRF) | 0.9039 +/- 0.0205 | 0.5750 +/- 0.0350 | 0.3798 +/- 0.0289 |

2. Kisa kategori sorgularinda uc yontem birbirinden AYIRT EDILEMIYOR

3. Insan caption sorgularinda hibrit CLIP'ten GERIDE (MRR farki 3+

   caption'lari uzerinde calistigi icin insan cumlelerinde gurultulu

## Faz 6 - Eslemeli Bootstrap: Hibrit Kisa Sorgularda CLIP'ten GERIDE

evaluate_v2.py'deki farklarin gercek olup olmadigini test etmek icin
eslemeli bootstrap (10.000 tekrar, seed=42, sorgular yerine koyarak
yeniden cekildi, %95 guven araligi) uygulandi. Ortalamalar
evaluate_v2 ile birebir ayni cikti (tutarlilik kontrolu gecti).

| Metrik | Karsilastirma | Ort. fark | %95 aralik | Sonuc |
|---|---|---|---|---|
| P@5 (kategori) | Hibrit - CLIP | +0.0312 | [-0.0052, +0.0675] | Ayirt edilemiyor |
| P@5 (kategori) | Hibrit - BM25 | +0.0519 | [+0.0078, +0.0961] | Sinirda (asagiya bak) |
| Recall@5 (caption) | Hibrit - CLIP | -0.0800 | [-0.1350, -0.0300] | Hibrit daha kotu |
| Recall@5 (caption) | Hibrit - BM25 | +0.3650 | [+0.2900, +0.4400] | Hibrit daha iyi |
| MRR@5 (caption) | Hibrit - CLIP | -0.1428 | [-0.1907, -0.0945] | Hibrit daha kotu |
| MRR@5 (caption) | Hibrit - BM25 | +0.2671 | [+0.2160, +0.3195] | Hibrit daha iyi |

Bulgular:
1. Hibrit, insan caption sorgularinda CLIP'ten GERCEKTEN geride. Bu,
   "gercekci sorguda hibrit one cikar" beklentisini kismen curutuyor.
2. Hibrit, BM25'ten acik ara iyi.
3. Kategori setinde hibrit-CLIP farki ayirt edilemiyor; hibritin
   ustunlugu iddia EDILEMEZ.
4. Hibrit-BM25 (kategori, P@5) alt siniri +0.008, sinirda. 6
   karsilastirma yapildigi icin yaklasik (tam Bonferroni degil) bir
   duzeltmeyle aralik 0'i icerir; bu sonuc "gercek" olarak raporlanmaz.
   Caption setindeki hibrit-CLIP farklari ayni duzeltmeyle buyuk
   olasilikla anlamli kalir (hesap dogrulanmadi, yaklasik).

Olasi neden (OLCULMEDI, hipotez): BM25, BLIP'in kisa/genel caption'lari
uzerinde calisiyor; insan cumlelerindeki kelimeler orada gecmedigi icin
siralamasi gurultulu, esit agirlikli RRF bu gurultuyu CLIP'e karistiriyor.
Sonraki adim bu hipotezi agirlikli RRF ile sinamak.

## Faz 6 - Agirlikli RRF Denemesi: BM25'e Agirlik Vermek Hibriti Kurtarmadi

Soru: BM25'e dusuk agirlik verilirse hibrit, CLIP'e yetisir mi?

Tasarim (sonuclar gorulmeden sabitlendi): rerank.py'ye istege bagli
"agirliklar" parametresi eklendi (varsayilan esit agirlik; eski
davranis birebir korundu, rerank.py testi ayni ciktiyi verdi). CLIP
agirligi 1.0'da sabit, BM25 agirligi {0, 0.1, 0.2, 0.3, 0.5, 0.75, 1.0}.
RRF k=60 ve aday havuzu (20) degistirilmedi. Agirlik SADECE dev setinde
secildi: test setindeki 200 gorselin DISINDAN 500 gorsel, seed=7,
gorsel basina rastgele bir insan caption'i (assert ile test ile
ortusmedigi dogrulandi). Secim kurali: dev MRR@5 en yuksek agirlik,
esitlikte kucuk. Secilen agirlik test setlerinde BIR KEZ olculdu.

Dev sonuclari (500 sorgu):

| BM25 agirligi | Recall@5 | MRR@5 |
|---|---|---|
| 0.0 | 0.6600 | 0.4950 |
| 0.1 | 0.6500 | 0.4595 |
| 0.2 | 0.6220 | 0.4184 |
| 0.3 | 0.6020 | 0.4002 |
| 0.5 | 0.6020 | 0.3959 |
| 0.75 | 0.6000 | 0.3900 |
| 1.0 | 0.5560 | 0.3679 |

Secilen agirlik: 0.0 (saf CLIP). Egri neredeyse tek yonlu dusuyor.
Komsu agirliklar arasindaki tek tek farklar standart hata icinde,
guvenilir olan egrinin GENEL YONU ve uclar arasindaki fark. w=0'in
izgara kenarinda cikmasi izgara darligi degil: CLIP-only zaten alt
sinir, yani BM25'in eklenen her payi bu sorgu turunda sonucu kotulestiriyor.

Test sonuclari: onceki sonuclarla birebir tutarli (kontrol satirlari
gecti). Insan caption: secilen (=CLIP) Recall 0.6550, MRR 0.5226;
esit agirlikli hibrit 0.5750, 0.3798. Kategori P@5: secilen 0.8727,
esit 0.9039 (fark -0.0312, aralik [-0.0675, +0.0052], ayirt edilemiyor).
NOT: test setinde "secilen - esit" karsilastirmasi, onceki bootstrap'in
isaret cevrilmis AYNISIDIR (secilen = CLIP); yeni kanit sayilmaz.
Bagimsiz dogrulama dev setidir (ayni yon, 500 farkli gorsel).

Sonuc: BLIP caption'lari uzerindeki BM25 ile kurdugumuz hibrit, cumle
tarzi sorgularda CLIP'ten kotu, kisa kategori sorgularinda ayirt
edilemez; agirlikla kurtarilamadi. Nedeni hala OLCULMEDI.

Sinirlar: agirlik sadece insan-caption sorgularinda secildi (kategori
icin ayri dev seti yok). Sadece BM25 agirligi arandi (RRF k ve havuz
boyutu sabit). Uretim kodu (hibrit_ara, akilli_ara) DEGISTIRILMEDI;
hibritin varsayilan kalip kalmayacagi acik karar.

Sonraki adim: BM25'in CLIP'in kacirdigini hic yakalayip yakalamadigini
(tamamlayicilik) sorgu bazli sonuclardan olcmek.

# ============================================================
# Bu script, data/raw_images klasorundeki gorseller icin BLIP ile
# otomatik caption (aciklama) uretir ve data/metadata.json dosyasina
# kaydeder.
#
# ONCE KUCUK OLCEKTE TEST EDIYORUZ: MAKS_GORSEL_SAYISI ile sinirli
# bir alt kumede calistirip SUREYI OLCECEGIZ. Bu sure bilgisiyle,
# TUM 5.000 gorsel icin ne kadar surecegini HESAPLAYIP, ondan sonra
# tam calistirmaya karar verecegiz - CLIP'te yaptigimiz gibi
# "once olc, sonra buyu" mantigini burada da uyguluyoruz.
# ============================================================

import os
import json
import time

from caption_generator import generate_caption

GORSEL_KLASORU = "data/raw_images"
METADATA_DOSYASI = "data/metadata.json"

# Once kucuk bir alt kumede test ediyoruz - TUM veri setine
# (5.000) gecmeden once suphesiz sure tahmini yapabilmek icin.
MAKS_GORSEL_SAYISI = 5000


def calistir():
    tum_dosyalar = [f for f in os.listdir(GORSEL_KLASORU) if f.endswith(".jpg")]
    secilen_dosyalar = tum_dosyalar[:MAKS_GORSEL_SAYISI]

    print(f"{len(secilen_dosyalar)} gorsel icin caption uretilecek...")
    print("(Bu bir SURE OLCUM testi - once kucuk oornekte deniyoruz)\n")

    metadata_listesi = []
    baslangic_zamani = time.time()

    for i, dosya_adi in enumerate(secilen_dosyalar):
        tam_yol = os.path.join(GORSEL_KLASORU, dosya_adi)
        try:
            caption = generate_caption(tam_yol)
            metadata_listesi.append({
                "dosya": tam_yol,
                "caption": caption,
            })
        except Exception as hata:
            print(f"HATA ({dosya_adi}): {hata}")

        # Her 50 gorselde bir ilerleme durumu yazdiralim, boylece
        # islemin canli oldugunu gorebiliriz (BLIP tek tek islendigi
        # icin bir ilerleme cubugu tqdm ile de kurulabilirdi, ama
        # burada basit bir sayac yeterli).
        if (i + 1) % 50 == 0:
            gecen_sure = time.time() - baslangic_zamani
            gorsel_basina_ortalama = gecen_sure / (i + 1)
            print(f"  {i+1}/{len(secilen_dosyalar)} islendi... "
                  f"(gorsel basina ortalama: {gorsel_basina_ortalama:.2f} saniye)")

    toplam_sure = time.time() - baslangic_zamani

    # Sonuclari diske kaydediyoruz.
    with open(METADATA_DOSYASI, "w", encoding="utf-8") as f:
        json.dump(metadata_listesi, f, ensure_ascii=False, indent=2)

    # ------------------------------------------------------------
    # SURE TAHMINI: 500 gorsel icin gecen sureden yola cikarak,
    # 5.000 gorsel (yani 10 kati) icin ne kadar surecegini
    # HESAPLIYORUZ - henuz gercekten 5.000'i islemeden once.
    # ------------------------------------------------------------
    gorsel_basina_ortalama = toplam_sure / len(secilen_dosyalar)
    tahmini_5000_suresi_dakika = (gorsel_basina_ortalama * 5000) / 60

    print(f"\n--- SURE RAPORU ({len(secilen_dosyalar)} gorsel) ---")
    print(f"Toplam sure: {toplam_sure:.1f} saniye ({toplam_sure/60:.2f} dakika)")
    print(f"Gorsel basina ortalama: {gorsel_basina_ortalama:.3f} saniye")
    print(f"\n>>> TAHMIN: 5.000 gorselin TAMAMI icin yaklasik "
          f"{tahmini_5000_suresi_dakika:.1f} dakika surer <<<")
    print(f"\nKaydedilen dosya: {METADATA_DOSYASI} ({len(metadata_listesi)} kayit)")


if __name__ == "__main__":
    calistir()

# ============================================================
# Bu script, data/raw_images klasorundeki TUM gorselleri (5.000
# tane) CLIP'ten gecirip embedding'lerini cikarir ve diske kaydeder.
#
# ONCEKI VERSIYONDAN FARKI: Artik gorselleri TEK TEK degil, encode_
# images_batch() fonksiyonuyla GRUPLAR HALINDE (batch_size=32)
# isliyoruz - bu, ozellikle GPU'da ama CPU'da da belirgin bir hiz
# kazanci saglar. Ayrica islemin TOPLAM SURESINI de olcup ekrana
# yazdiriyoruz - bu sayi, Faz 6'daki README'de "5.000 gorsel icin
# embedding cikarma X dakika surdu" seklinde somut bir veri olarak
# kullanilacak.
# ============================================================

import os
import json
import time
import numpy as np

from clip_encoder import encode_images_batch

GORSEL_KLASORU = "data/raw_images"

EMBEDDING_DOSYASI = "data/full_embeddings.npy"
YOL_LISTESI_DOSYASI = "data/full_image_paths.json"

# Her seferde kac gorselin AYNI ANDA islenecegi. 32, CPU/GPU
# bellek kullanimi ile hiz arasinda dengeli bir tercih - cok
# buyutursen (orn. 256) bellek yetersiz kalabilir, cok kucultursen
# (orn. 4) batch'in hiz avantaji azalir.
BATCH_SIZE = 32


def calistir():
    # os.listdir(): klasordeki TUM dosya/klasor isimlerini bir liste
    # olarak doner. endswith(".jpg") ile sadece .jpg uzantili
    # dosyalari filtreliyoruz (baska dosya turu varsa almiyoruz).
    tum_dosyalar = [f for f in os.listdir(GORSEL_KLASORU) if f.endswith(".jpg")]

    # Sadece dosya isimlerini degil, TAM YOLLARI (klasor + dosya adi)
    # olusturuyoruz - encode_images_batch() fonksiyonu tam yol bekliyor.
    tum_yollar = [os.path.join(GORSEL_KLASORU, f) for f in tum_dosyalar]

    print(f"{len(tum_yollar)} gorsel islenecek (batch_size={BATCH_SIZE})...")

    # time.time(): programin o anki calisma zamanini (saniye cinsinden,
    # bir referans noktasina gore) verir. Islem oncesi ve sonrasi bu
    # degeri alip farkini hesaplayarak, islemin ne kadar surdugunu
    # olcebiliyoruz.
    baslangic_zamani = time.time()

    # ISTE ANA ISLEM: tum gorselleri batch batch isleyip, hem
    # embedding matrisini hem de basariyla islenen dosyalarin
    # yollarini geri aliyoruz.
    embedding_matrisi, basarili_yollar = encode_images_batch(
        tum_yollar, batch_size=BATCH_SIZE
    )

    gecen_sure_saniye = time.time() - baslangic_zamani

    # Diske kaydediyoruz - onceki versiyonla ayni mantik.
    np.save(EMBEDDING_DOSYASI, embedding_matrisi)
    with open(YOL_LISTESI_DOSYASI, "w") as f:
        json.dump(basarili_yollar, f)

    # ------------------------------------------------------------
    # SURE RAPORU: Bu kisim yeni. Toplam sureyi hem saniye hem
    # dakika cinsinden, hem de "gorsel basina ortalama sure" olarak
    # yazdiriyoruz - Faz 6'daki README'de kullanmak icin.
    # ------------------------------------------------------------
    dakika = gecen_sure_saniye / 60
    gorsel_basina_ms = (gecen_sure_saniye / len(basarili_yollar)) * 1000

    print(f"\nBitti! {embedding_matrisi.shape} boyutunda bir matris kaydedildi.")
    print(f"Kaydedilen dosyalar: {EMBEDDING_DOSYASI}, {YOL_LISTESI_DOSYASI}")
    print(f"\n--- SURE RAPORU ---")
    print(f"Toplam sure: {gecen_sure_saniye:.1f} saniye ({dakika:.2f} dakika)")
    print(f"Gorsel basina ortalama: {gorsel_basina_ms:.2f} ms")
    print(f"Islenen gorsel sayisi: {len(basarili_yollar)} / {len(tum_yollar)}")


if __name__ == "__main__":
    calistir()

# ============================================================
# Bu dosya, BLIP modelini kullanarak bir gorsele bakip, o gorseli
# ACIKLAYAN bir metin (caption) uretir. Ornek: bir kopek fotografini
# verirsen, "a dog running in a park" gibi bir cumle doner.
#
# BU NEDEN ONEMLI? CLIP, gorseli dogrudan bir vektore ceviriyordu -
# ama BM25 (Faz 3'un bir sonraki adiminda yazacagimiz) klasik
# anahtar kelime aramasi, VEKTOR degil METIN uzerinde calisir.
# Yani gorsellerimizin "aranabilir" bir metin karsiligina ihtiyacimiz
# var - BLIP bize bunu sagliyor.
#
# CLIP ile BLIP'in farki: CLIP "bu gorsel ile bu metin ne kadar
# benzer" diye KARSILASTIRMA yapar. BLIP ise "bu gorsel ne anlatiyor"
# diye SIFIRDAN bir cumle URETIR (generation). Farkli bir model,
# farkli bir gorev.
# ============================================================

import torch
from transformers import BlipProcessor, BlipForConditionalGeneration
from PIL import Image

# Ayni CLIP'te oldugu gibi, GPU varsa onu kullaniyoruz, yoksa CPU.
device = "cuda" if torch.cuda.is_available() else "cpu"

# BlipProcessor: gorseli, BLIP modelinin bekledigi formata (boyut,
# normalize edilmis piksel degerleri vb.) donusturen arac - CLIP'teki
# "preprocess" fonksiyonuna benzer bir gorevi var.
#
# "Salesforce/blip-image-captioning-base": Salesforce firmasinin
# yayinladigi, gorsellere aciklama uretmek icin ozel egitilmis,
# nispeten kucuk/hizli bir BLIP modeli (daha buyuk "large" versiyonu
# da var ama base, ogrenme asamasi icin yeterli ve daha hizli).
model_adi = "Salesforce/blip-image-captioning-base"

processor = BlipProcessor.from_pretrained(model_adi)
model = BlipForConditionalGeneration.from_pretrained(model_adi).to(device)

# model.eval(): CLIP'te oldugu gibi, modeli "sadece kullanim" moduna
# aliyoruz, egitim sirasinda kullanilan rastgelelik iceren islemleri
# kapatiyoruz.
model.eval()


def generate_caption(image_path):
    """
    Bir gorsel dosyasinin yolunu alir, BLIP ile o gorseli aciklayan
    bir cumle (caption) uretir ve metni geri dondurur.
    """
    # Gorseli ac, RGB'ye cevir (CLIP'teki ile ayni sebep - model hep
    # 3 renk kanalli gorsel bekler).
    gorsel = Image.open(image_path).convert("RGB")

    # processor(gorsel, return_tensors="pt"): gorseli modele
    # verilecek forma getirir. "pt" = PyTorch tensoru formatinda
    # dondur demek (baska kutuphaneler icin "tf" (TensorFlow) gibi
    # secenekler de olabilir, biz PyTorch kullandigimiz icin "pt").
    girdi = processor(gorsel, return_tensors="pt").to(device)

    with torch.no_grad():
        # model.generate(): BLIP'e "bu gorsel icin bir cumle URET"
        # diyoruz. Bu, CLIP'teki encode_image()'dan FARKLI bir islem -
        # orada tek bir vektor donuyordu, burada modelin kelime kelime
        # URETTIGI bir cumlenin token (sayisal kod) hali donuyor.
        #
        # max_new_tokens=30: modelin uretecegi cumlenin en fazla kac
        # kelime/parca (token) uzunlugunda olabilecegini sinirliyoruz -
        # cok uzun, gereksiz detayli cumleler uretmesini engelliyoruz.
        cikti = model.generate(**girdi, max_new_tokens=30)

    # processor.decode(): modelin urettigi sayisal token'lari, tekrar
    # OKUNABILIR bir metne (insan dili cumlesine) ceviriyoruz.
    # skip_special_tokens=True: modelin ic mekanizmasinda kullandigi,
    # "cumle burada basliyor/bitiyor" gibi ozel isaretleri (token'lari)
    # cikti metninden temizler - biz sadece duz, okunabilir cumleyi
    # istiyoruz.
    caption = processor.decode(cikti[0], skip_special_tokens=True)

    return caption


# Bu dosya dogrudan calistirildiginda, tek bir ornek gorsel uzerinde
# hizli bir test yapiyoruz.
if __name__ == "__main__":
    import os

    klasor = "data/raw_images"

        print("data/raw_images klasorunde hic .jpg dosyasi bulamadim!")
    else:
        # Ilk 3 gorseli test edelim, tek gorselle yetinmeyelim -
        # boylece modelin genel olarak makul cumleler urettigini
        # birden fazla ornekte gorebiliriz.
        for dosya_adi in dosyalar[:3]:
            tam_yol = os.path.join(klasor, dosya_adi)
            uretilen_caption = generate_caption(tam_yol)

import open_clip
from tqdm import tqdm
import numpy as np
from PIL import Image

# ============================================================
# ADIM 1: Hangi donanimda calisacagimizi belirliyoruz.
# Eger bilgisayarinda/Colab'da bir GPU (cuda) varsa onu kullan,
# yoksa normal islemciyi (cpu) kullan. GPU cok daha hizli calisir.

# ============================================================
# ADIM 2: CLIP modelini yukluyoruz.
# "ViT-B-32" -> modelin mimarisi (Vision Transformer, Base boyut, 32 patch)
# "laion2b_s34b_b79k" -> bu mimarinin hangi veriyle onceden egitildigi
# (LAION adli 2 milyar goeselli bir veri setiyle egitilmis, hazir agirliklar)
#
# create_model_and_transforms() bize UC sey veriyor:
#   model      -> asil sinir agi (embedding uretecek olan)
#   _          -> egitim icin kullanilan bir transform (biz kullanmiyoruz, o yuzden _ dedik)
#   preprocess -> gorselleri modele vermeden once nasil hazirlayacagimizi soyleyen fonksiyon
#                 (boyutlandirma, kirpma, normalizasyon gibi islemleri otomatik yapar)
# ============================================================
model, _, preprocess = open_clip.create_model_and_transforms(
    "ViT-B-32", pretrained="laion2b_s34b_b79k"
)

# tokenizer: bir metni (orn. "kirmizi araba") modelin anlayacagi sayisal
# forma (token'lara) ceviren arac. Goersel icin preprocess neyse, metin icin tokenizer o.
tokenizer = open_clip.get_tokenizer("ViT-B-32")

# Modeli sectigimiz cihaza (GPU/CPU) tasiyoruz.
model = model.to(device)

# model.eval(): modeli "degerlendirme moduna" aliyoruz.
# Bu, modelin egitim sirasinda kullandigi bazi rastgelelik iceren
# islemleri (dropout gibi) kapatir - biz egitmiyoruz, sadece kullaniyoruz.
model.eval()


def encode_image(image_path):
    """
    Bir gorsel dosyasinin yolunu (path) alir, CLIP'in urettigi
    512 boyutlu sayisal vektorunu (embedding) dondurur.
    """
    # Gorseli ac, RGB formatina cevir (bazi gorseller siyah-beyaz/farkli
    # formatta olabilir, CLIP hep RGB (3 renk kanali) bekler).
    image = Image.open(image_path).convert("RGB")

    # preprocess: gorseli modelin bekledigi boyuta/formata getirir.
    # unsqueeze(0): modele "tek bir gorsel gonderiyorum" demek icin
    # basina bir "batch boyutu" ekler (model normalde birden fazla
    # gorseli aynı anda islemek uzere tasarlanmis, biz tek gorsel
    # gonderdigimiz icin bu boyutu elle ekliyoruz).
    image_input = preprocess(image).unsqueeze(0).to(device)

    # torch.no_grad(): "gradyan hesaplama" (egitim icin gerekli olan
    # matematiksel takip) yapma diyoruz. Sadece tahmin/donusum
    # yaptigimiz icin bu, islemi hem hizlandirir hem bellek tasarrufu saglar.
    with torch.no_grad():
        vektor = model.encode_image(image_input)

        # L2 Normalizasyon: vektorun "uzunlugunu" 1'e esitliyoruz.
        # Bunu yapmazsak, iki vektor arasindaki benzerligi (cosine similarity)
        # dogru olcemeyiz - normalize edilmemis vektorlerde "buyukluk"
        # benzerlik hesabini bozar. Bu adim CLIP ile calisirken KRITIK.
        vektor = vektor / vektor.norm(dim=-1, keepdim=True)

    # GPU'daysa CPU'ya geri al, PyTorch tensorunu normal bir
    # numpy array'e cevir (diger kutuphanelerle -orn. FAISS- uyumlu olsun diye).
    # [0] ile "batch" boyutunu (basta elle ekledigimiz) kaldiriyoruz.
    return vektor.cpu().numpy()[0]


def encode_text(text):
    """
    Bir metin (orn. "kirmizi bir araba") alir, CLIP'in urettigi
    512 boyutlu sayisal vektorunu (embedding) dondurur.
    Yukaridaki encode_image ile MANTIK OLARAK AYNI islemi yapar,
    tek fark gorsel yerine metin isliyor olmasi.
    """
    # tokenizer bir liste bekler (birden fazla metni aynı anda
    # isleyebilmek icin), o yuzden text'i [text] seklinde listeye sariyoruz.
    text_input = tokenizer([text]).to(device)

    with torch.no_grad():
        vektor = model.encode_text(text_input)
        vektor = vektor / vektor.norm(dim=-1, keepdim=True)  # ayni normalize islemi

    return vektor.cpu().numpy()[0]

def encode_images_batch(image_paths, batch_size=32):
    """
    Birden fazla gorseli TEK TEK degil, gruplar (batch) halinde isler.

    Neden batch onemli? encode_image() fonksiyonu her cagrildiginda
    modelin "unsqueeze(0)" ile tek gorsellik sahte bir grup olusturdugunu
    hatirla - yani model aslinda hep gruplar halinde calismak icin
    tasarlanmis, biz onu 1'lik gruplarla kullaniyorduk. Bu, ozellikle
    GPU'da (ve biraz da CPU'da) verimsizdir - cunku donanim, ayni anda
    birden fazla gorseli islerken cok daha verimli calisir (paralel
    hesaplama). 32 gorseli TEK TEK islemek yerine, 32'sini AYNI ANDA
    modele vermek, toplam sureyi ciddi sekilde kisaltabilir - ozellikle
    buyuk veri setlerinde (bizim 5.000 gorselimizde bile fark yaratir).

    Parametreler:
        image_paths: islenecek TUM gorsellerin dosya yollarinin listesi
        batch_size: her seferde kac gorselin AYNI ANDA islenecegi
                    (32, yaygin ve dengeli bir tercih - cok buyuk
                    olursa bellek (RAM) yetersiz kalabilir, cok kucuk
                    olursa batch'in hiz avantaji azalir)

    Donus degeri:
        (N, 512) boyutunda bir numpy array - N = basarili islenen
        gorsel sayisi, her satir bir gorselin 512 boyutlu vektoru.
        Ayrica hangi dosyalarin basariyla islendigini de donuyoruz
        (bazi gorseller bozuk olabilir, onlari atlayabiliriz).
    """
    tum_vektorler = []
    basarili_yollar = []

    # range(0, len(image_paths), batch_size): 0'dan basla, listenin
    # sonuna kadar git, ama HER SEFERINDE batch_size kadar atla.
    # Ornek: 100 gorsel, batch_size=32 ise -> 0, 32, 64, 96 seklinde
    # 4 durak olusur (son grup sadece 4 gorsel icerir, o normal).
    for baslangic_index in tqdm(range(0, len(image_paths), batch_size)):
        # Su anki grubun (batch'in) icerdigi dosya yollarini aliyoruz.
        # Python'un "slice" (dilim) ozelligini kullaniyoruz:
        # liste[baslangic:bitis] o aralikdaki elemanlari verir.
        grup_yollari = image_paths[baslangic_index : baslangic_index + batch_size]

        # Bu gruptaki HER gorseli ac, on-isle (preprocess), ama henuz
        # modele VERME - once hepsini bir listede topluyoruz.
        grup_tensorleri = []
        gecerli_yollar_bu_grupta = []

        for yol in grup_yollari:
            try:
                gorsel = Image.open(yol).convert("RGB")
                # preprocess(gorsel) tek bir gorseli islenmis hale getirir,
                # ama unsqueeze(0) YAPMIYORUZ burada - cunku birazdan
                # hepsini tek seferde "yigin" (stack) halinde birlestirecegiz.
                islenmis = preprocess(gorsel)
                grup_tensorleri.append(islenmis)
                gecerli_yollar_bu_grupta.append(yol)
            except Exception as hata:
                print(f"HATA ({yol}): {hata}")

        if not grup_tensorleri:
            # Eger bu grupta islenebilen HICBIR gorsel yoksa
            # (hepsi bozuksa), bir sonraki gruba gec.
            continue

        # torch.stack(): tek tek islenmis gorselleri (her biri (3, 224, 224)
        # gibi bir boyutta) TEK BIR buyuk tensore birlestirir. Sonuc:
        # (batch_size, 3, 224, 224) boyutunda - yani "32 tane gorsel,
        # her biri 3 renk kanali, 224x224 piksel" seklinde tek bir paket.
        toplu_tensor = torch.stack(grup_tensorleri).to(device)

        with torch.no_grad():
            # ISTE FARK BURADA: model.encode_image() BIR KERE cagriliyor
            # ama icinde 32 gorsel birden var - model bunlari kendi
            # icinde PARALEL olarak isliyor, 32 ayri cagri yapmiyoruz.
            vektorler = model.encode_image(toplu_tensor)
            # Normalize etme islemi yine ayni - her satiri (her gorselin
            # vektorunu) kendi icinde 1 uzunluguna getiriyoruz.
            vektorler = vektorler / vektorler.norm(dim=-1, keepdim=True)

        # GPU'daysa CPU'ya al, numpy'a cevir, listemize ekle.
        tum_vektorler.append(vektorler.cpu().numpy())
        basarili_yollar.extend(gecerli_yollar_bu_grupta)

    # tum_vektorler su an kucuk parcalar halinde bir liste
    # (her biri (batch_size, 512) boyutunda). np.vstack() bunlari
    # dikey olarak (satir satir) tek bir buyuk array'de birlestirir.
    embedding_matrisi = np.vstack(tum_vektorler)

    return embedding_matrisi, basarili_yollar

# ============================================================
# Bu script, az once diske kaydettigimiz embedding'leri okuyup,
# bir metin sorgusu alip, o sorguya en "yakin" (en benzer) gorselleri
# bulan bir arama fonksiyonu icerir.
#
# Henuz FAISS kullanmiyoruz - sadece numpy ile matematiksel olarak
# "hangi gorsel vektoru, sorgu vektorune en yakin" hesabini yapiyoruz.
# ============================================================

import json
import numpy as np
from clip_encoder import encode_text

EMBEDDING_DOSYASI = "data/test_embeddings.npy"
YOL_LISTESI_DOSYASI = "data/test_image_paths.json"


def sorgu_ara(sorgu_metni, k=5):
    """
    sorgu_metni: aranacak metin (orn. "a red car")
    k: kac tane sonuc dondurulecek (varsayilan 5)
    """
    # Daha once kaydettigimiz embedding matrisini ve dosya yollarini geri yukluyoruz.
    embedding_matrisi = np.load(EMBEDDING_DOSYASI)  # (300, 512) boyutunda
    with open(YOL_LISTESI_DOSYASI, "r") as f:
        image_paths = json.load(f)

    # Sorgu metnini de ayni 512 boyutlu vektor uzayina ceviriyoruz.
    sorgu_vektoru = encode_text(sorgu_metni)  # (512,) boyutunda

    # ============================================================
    # ISTE ISIN KALBI: Cosine Similarity Hesabi
    #
    # embedding_matrisi: (300, 512)  -> 300 gorsel, her biri 512 sayidan olusuyor
    # sorgu_vektoru:      (512,)     -> 1 sorgu, 512 sayidan olusuyor
    #
    # embedding_matrisi @ sorgu_vektoru -> matris carpimi.
    # Bu islem, HER gorsel vektoru ile sorgu vektoru arasinda "ic carpim"
    # (dot product) hesaplar ve sonucta (300,) boyutunda bir liste doner -
    # yani her gorsel icin TEK BIR benzerlik skoru.
    #
    # Neden bu bir "cosine similarity" oluyor? Cunku clip_encoder.py'de
    # her iki vektoru de L2 normalize etmistik (uzunluklarini 1 yapmistik).
    # Uzunlugu 1 olan iki vektorun ic carpimi = aralarindaki acinin kosinusu
    # = cosine similarity. Normalize etmeseydik bu formul GECERSIZ olurdu.
    #
    # Skor -1 ile 1 arasinda olur: 1'e yakinsa "cok benzer",
    # 0'a yakinsa "alakasiz", -1'e yakinsa "zit anlamli" (CLIP'te nadir gorulur).
    # ============================================================
    benzerlik_skorlari = embedding_matrisi @ sorgu_vektoru

    # np.argsort(): skorlari KUCUKTEN BUYUGE siralar, ama biz index (sira
    # numarasi) istiyoruz, deger degil. [::-1] ile ters ceviriyoruz ki
    # BUYUKTEN KUCUGE olsun (en benzer en basta olsun).
    # [:k] ile sadece ilk k taneyi aliyoruz.
    en_iyi_indeksler = np.argsort(benzerlik_skorlari)[::-1][:k]

    print(f"\n'{sorgu_metni}' icin en iyi {k} sonuc:\n")
    for sira, indeks in enumerate(en_iyi_indeksler, start=1):
        dosya_yolu = image_paths[indeks]
        skor = benzerlik_skorlari[indeks]
        print(f"{sira}. {dosya_yolu}  (benzerlik skoru: {skor:.3f})")

    import matplotlib.pyplot as plt

# ============================================================
# Bu script, kurdugumuz 3 index tipini (Flat, IVF, HNSW) HIZ ve
# DOGRULUK acisindan karsilastirir.
#
# Dogruluk nasil olculur? Flat index %100 dogru kabul edilir
# (cunku o, TUM vektorleri tek tek karsilastirir - yanilma sansi
# yok). IVF ve HNSW'nin bulduğu sonuclarin, Flat'in bulduğu
# sonuclarla NE KADAR ORTUSTUGUNE bakariz. Ortusme orani ne kadar
# yuksekse, o index o kadar "guvenilir" demektir.
#
# BU VERSIYONDA IKI IYILESTIRME VAR:
#   1. Sorgu sayisi 10'dan 25'e cikarildi - daha genis bir ornek
#      uzerinden olcum yapmak, tesadufi sapmalari azaltir.
#   2. Her sorgu icin arama, TEK SEFER degil 5 KEZ tekrarlanip
#      ortalamasi aliniyor - cunku bilgisayarin o anki yuku
#      (baska programlar, isletim sistemi islemleri vb.) tek bir
#      olcumu hafifce carpitabilir. Ortalama almak bu "gurultuyu"
#      azaltir, daha guvenilir bir sure verir.
# ============================================================

import faiss
import numpy as np
import json
import time
import sys
import os

# clip_encoder.py, embeddings klasorunde - onu buradan import
# edebilmek icin Python'a "embeddings klasorune de bak" diyoruz.
# sys.path, Python'un "import ederken hangi klasorlere bakayim"
# diye kontrol ettigi liste - buraya embeddings klasorunun tam
# yolunu ekliyoruz.
sys.path.append(os.path.join(os.path.dirname(__file__), "..", "embeddings"))
from clip_encoder import encode_text

EMBEDDING_DOSYASI = "data/full_embeddings.npy"
YOL_LISTESI_DOSYASI = "data/full_image_paths.json"

# Test edecegimiz sorgular - 25 tane, COCO veri setinde sikca
# gecen kategorileri (kopek, kedi, bisiklet, araba, mobilya vb.)
# ve biraz daha soyut/genel ifadeleri karisik olarak iceriyor.
TEST_SORGULARI = [
    "a dog",
    "a cat",
    "food on a table",
    "a person riding a bike",
    "a car on the street",
    "a group of people",
    "a bathroom",
    "an airplane",
    "a laptop computer",
    "a bowl of fruit",
    "a person playing tennis",
    "a kitchen",
    "a living room with a couch",
    "a busy street",
    "a train",
    "a boat on water",
    "children playing",
    "a birthday cake",
    "a snowy mountain",
    "a beach",
    "a stop sign",
    "an umbrella",
    "a clock",
    "a teddy bear",
    "a pizza",
]

K = 10  # her sorgu icin ilk kac sonuca bakacagiz

# Her sorguyu kac kez tekrarlayip ortalama alacagimiz. 5 tekrar,
# olcumdeki tesadufi sapmalari makul bir surede azaltmaya yeter -
# cok fazla tekrar (orn. 100) hem gereksiz uzun surer hem de
# bu olcek icin ek bir dogruluk kazandirmaz.
TEKRAR_SAYISI = 5


def index_yukle():
    """
    Faiss_index.py'de diske kaydettigimiz 3 index dosyasini
    (flat_index.faiss, ivf_index.faiss, hnsw_index.faiss) geri okur.
    """
    return {
        "flat": faiss.read_index("index/flat_index.faiss"),
        "ivf": faiss.read_index("index/ivf_index.faiss"),
        "hnsw": faiss.read_index("index/hnsw_index.faiss"),
    }


def benchmark_calistir():
    print("Index'ler yukleniyor...")
    indexler = index_yukle()

    # Her index tipi icin, tum sorgular boyunca biriken TOPLAM
    # sureyi ve (Flat haric) ortusme oranlarini burada toplayacagiz.
    sonuclar = {isim: {"toplam_sure": 0.0, "ortusme_oranlari": []} for isim in indexler}

    print(f"{len(TEST_SORGULARI)} sorgu, her biri {TEKRAR_SAYISI} kez tekrarlanacak...\n")

    # Her sorgu icin, UCU DE index'te ayni sorguyla arama yapacagiz.
    for sorgu in TEST_SORGULARI:
        # Sorguyu vektore ceviriyoruz - bu islemi sorgu basina SADECE
        # BIR KEZ yapiyoruz (metni vektore cevirmek de zaman alir,
        # ama biz sadece ARAMA suresini olcmek istiyoruz, embedding
        # cikarma suresini degil - o yuzden bunu tekrar dongusunun
        # DISINDA yapiyoruz).
        sorgu_vektoru = encode_text(sorgu).reshape(1, -1).astype("float32")

        # Flat index'in bulduğu sonuclari burada saklayacagiz - digerlerini
        # bununla (dogru kabul ettigimiz referansla) karsilastiracagiz.
        flat_sonuc_indeksleri = None

        for isim, index in indexler.items():
            # Bu sorgu + bu index icin yapilan TUM tekrarlarin
            # surelerini burada topluyoruz.
            bu_kombinasyonun_sureleri = []

            for tekrar in range(TEKRAR_SAYISI):
                baslangic = time.time()
                _, I = index.search(sorgu_vektoru, K)
                gecen_sure = time.time() - baslangic
                bu_kombinasyonun_sureleri.append(gecen_sure)

            # 5 tekrarin ORTALAMASINI aliyoruz - tek bir olcume
            # guvenmek yerine.
            ortalama_sure = np.mean(bu_kombinasyonun_sureleri)
            sonuclar[isim]["toplam_sure"] += ortalama_sure

            # Dogruluk (ortusme) karsilastirmasi icin en son yapilan
            # aramanin sonucunu kullaniyoruz (hepsi ayni sonucu
            # verir zaten, cunku ayni sorgu ayni index'te araniyor -
            # sadece SURE olcumu tekrarlaniyor, sonuc degismez).
            if isim == "flat":
                flat_sonuc_indeksleri = set(I[0])
            else:
                bu_sonuc = set(I[0])
                ortusen = len(bu_sonuc & flat_sonuc_indeksleri)
                oran = ortusen / K
                sonuclar[isim]["ortusme_oranlari"].append(oran)

    # ------------------------------------------------------------
    # Sonuclari okunakli bir tabloya dokuyoruz.
    #
    # Not: Basliklari degiskenlere atadik cunku "Flat'e Gore" gibi
    # icinde Turkce kesme isareti (') olan bir metni dogrudan f-string
    # icinde yazarsak, Python o kesme isaretini string'in bittigi yer
    # saniyor ve SyntaxError veriyor. Degiskene atayip f-string icinde
    # sadece degiskeni kullanmak bu sorunu tamamen ortadan kaldirir.
    # ------------------------------------------------------------
    baslik_1 = "Index Tipi"
    baslik_2 = "Ort. Sure (ms)"
    baslik_3 = "Flat ile Ortusme"

    print(f"\n{baslik_1:<10} {baslik_2:<18} {baslik_3:<20}")
    print("-" * 50)

    for isim, veri in sonuclar.items():
        # Ortalama sureyi saniyeden milisaniyeye ceviriyoruz (*1000)
        # cunku bu kadar kucuk sureler icin ms daha okunakli.
        ort_sure_ms = (veri["toplam_sure"] / len(TEST_SORGULARI)) * 1000

        if isim == "flat":
            referans_yazisi = "(referans)"
            print(f"{isim:<10} {ort_sure_ms:<18.3f} {referans_yazisi:<20}")
        else:
            ort_ortusme = np.mean(veri["ortusme_oranlari"]) * 100
            print(f"{isim:<10} {ort_sure_ms:<18.3f} {ort_ortusme:<20.1f}%")


if __name__ == "__main__":
    benchmark_calistir()

# ============================================================
# Bu dosya, BLIP'in urettigi caption'lar (metin aciklamalar) uzerinde
# KLASIK ANAHTAR KELIME ARAMASI yapan bir BM25 index'i kurar.
#
# BM25 NEDIR? "Best Matching 25" - arama motorlarinin (eskiden
# Google'in bile) kullandigi, kelime frekansina dayali klasik bir
# siralama algoritmasi. CLIP'in yaptigi "anlam benzerligi" (semantic
# similarity) ile TAMAMEN FARKLI bir mantik kullanir:
#
#   CLIP (semantic): "kirmizi araba" yazinca, o kelimeleri metin
#   olarak icermeyen ama ANLAM olarak alakali gorselleri de bulabilir
#   (orn. caption'da "araba" gecmese bile gorselin CLIP vektoru
#   "araba" ile yakinsa bulunur).
#
#   BM25 (keyword/anahtar kelime): "kirmizi araba" yazinca, SADECE
#   caption'inda GERCEKTEN "kirmizi" VE/VEYA "araba" KELIMELERI GECEN
#   sonuclari bulur. Anlam onemli degil, KELIMENIN KENDISI onemli.
#
# NEDEN IKISINE DE IHTIYACIMIZ VAR? Cunku bazen kullanici cok spesifik
# bir kelime arar (orn. bir marka ismi, bir ozel isim) ve CLIP bunu
# "anlamca" yakalayamayabilir - BM25 boyle durumlarda daha guvenilir.
# Bir sonraki adimda (hybrid_search.py) ikisini BIRLESTIRECEGIZ.
# ============================================================

import json
from rank_bm25 import BM25Okapi

METADATA_DOSYASI = "data/metadata.json"


def bm25_index_kur():
    """
    metadata.json'daki tum caption'lari okuyup, bir BM25 index'i
    kurar. Ayrica, sonuc dondururken hangi index numarasinin hangi
    gorsele ait oldugunu bilmemiz gerektigi icin, dosya yollarinin
    listesini de geri donduruyoruz.
    """
    with open(METADATA_DOSYASI, "r", encoding="utf-8") as f:
        metadata_listesi = json.load(f)

    # BM25, her belgeyi (bizim durumumuzda her caption'i) bir KELIME
    # LISTESI olarak bekler, tek bir cumle (string) olarak degil.
    # Ornek: "a dog running in a park" -> ["a", "dog", "running", "in", "a", "park"]
    # .split() fonksiyonu, bir metni bosluklardan bolerek kelime
    # listesine cevirir - basit ama etkili bir "tokenization" yontemi.
    tokenize_edilmis_caption_listesi = [
        kayit["caption"].lower().split() for kayit in metadata_listesi
    ]
    # .lower(): tum harfleri kucuk harfe ceviriyoruz - boylece "Dog"
    # ile "dog" ayni kelime olarak sayilir, buyuk/kucuk harf farki
    # aramayi etkilemez.

    # BM25Okapi: rank_bm25 kutuphanesinin sundugu, en yaygin kullanilan
    # BM25 versiyonu. Kendisine tokenize edilmis (kelimelere bolunmus)
    # belgelerin (caption'larin) listesini veriyoruz, o da kendi
    # icinde hangi kelimenin hangi belgede kac kere gectigini
    # hesaplayip bir "index" olusturuyor.
    bm25 = BM25Okapi(tokenize_edilmis_caption_listesi)

    # Hangi index numarasinin (0, 1, 2, ...) hangi GORSEL DOSYASINA
    # ait oldugunu bilmemiz lazim - bu listeyi de saklayip donduruyoruz.
    # Ayni "\" / "/" sorunu burada da var - normalize ediyoruz.
    dosya_yollari = [kayit["dosya"].replace("\\", "/") for kayit in metadata_listesi]
    caption_listesi = [kayit["caption"] for kayit in metadata_listesi]

    return bm25, dosya_yollari, caption_listesi


def bm25_ara(bm25, dosya_yollari, caption_listesi, sorgu, k=10):
    """
    Verilen bir BM25 index'inde, sorgu metnine gore arama yapar.

    sorgu: aranacak metin (orn. "a red car")
    k: kac tane sonuc dondurulecek
    """
    # Sorguyu da AYNI SEKILDE (kucuk harfe cevirip kelimelere bolerek)
    # hazirliyoruz - index'i olustururken kullandigimiz yontemle
    # TUTARLI olmasi lazim, yoksa karsilastirma anlamsiz olur.
    sorgu_kelimeleri = sorgu.lower().split()

    # bm25.get_scores(): verilen sorgu kelimelerine gore, index'teki
    # HER BIR belge (caption) icin bir BM25 skoru hesaplar. Sonuc,
    # belge sayisi kadar uzunlukta bir sayi listesi doner - her sayi,
    # o caption'in sorguyla ne kadar "eslesip eslesmedigini" gosterir
    # (yuksek skor = daha alakali).
    skorlar = bm25.get_scores(sorgu_kelimeleri)

    # numpy kullanmadan, Python'un kendi araclariyla en yuksek skorlu
    # k taneyi buluyoruz. sorted() ile (index, skor) ciftlerini
    # skora gore BUYUKTEN KUCUGE siraliyoruz (reverse=True), sonra
    # ilk k taneyi aliyoruz.
    indeks_skor_ciftleri = list(enumerate(skorlar))
    siralanmis = sorted(indeks_skor_ciftleri, key=lambda x: x[1], reverse=True)
    en_iyi_k = siralanmis[:k]

    sonuclar = []
    for indeks, skor in en_iyi_k:
        sonuclar.append({
            "dosya": dosya_yollari[indeks],
            "caption": caption_listesi[indeks],
            "skor": skor,
        })

    return sonuclar

            print(f"{sira}. {sonuc['caption']}  (skor: {sonuc['skor']:.2f})")
        print()

# ============================================================
# Bu dosya, FAISS kutuphanesini kullanarak 3 FARKLI index tipi
# kurar. Amac: hangi index tipinin bizim veri boyutumuz (5.000
# gorsel) icin en iyi hiz/dogruluk dengesini verdigini olcmek.
#
# Ucu de ayni islevi gorur ("en yakin vektorleri bul") ama farkli
# yontemlerle:
#
# 1. FLAT   -> "Kaba kuvvet". Sorgu vektorunu, TUM 5.000 vektorle
#              tek tek karsilastirir. En yavas ama %100 dogru -
#              bunu "dogru cevap" referansi olarak kullanacagiz.
#
# 2. IVF    -> "Inverted File Index". Once tum vektorleri gruplara
#              (kumelere) ayirir, sorgu geldiginde sadece en yakin
#              birkac grubun icinde arama yapar. Cok daha hizli
#              ama YAKLASIK sonuc verir (en iyi sonucu kacirabilir).
#
# 3. HNSW   -> "Hierarchical Navigable Small World". Vektorler
#              arasinda bir "graf" (agac benzeri baglanti yapisi)
#              kurar, aramayi bu graf uzerinde gezerek yapar.
#              Genelde IVF'den daha dogru, Flat'ten daha hizlidir -
#              hiz/dogruluk dengesi en iyi olan tip genelde budur.
# ============================================================

import faiss
import numpy as np
import json
import time

EMBEDDING_DOSYASI = "data/full_embeddings.npy"
YOL_LISTESI_DOSYASI = "data/full_image_paths.json"


def index_kur(embedding_matrisi):
    """
    Ayni embedding matrisinden UC farkli index kurar ve hepsini
    bir sozlukte (dictionary) dondurur.
    """
    boyut = embedding_matrisi.shape[1]  # 512 (her vektorun uzunlugu)
    n = embedding_matrisi.shape[0]  # 5000 (kac vektor oldugu)

    # ------------------------------------------------------------
    # 1. FLAT INDEX
    # IndexFlatIP: "IP" = Inner Product (ic carpim). Vektorler
    # normalize edilmis oldugu icin bu, cosine similarity'ye esdeger.
    # ------------------------------------------------------------
    flat_index = faiss.IndexFlatIP(boyut)
    flat_index.add(embedding_matrisi)  # tum vektorleri index'e ekle

    # ------------------------------------------------------------
    # 2. IVF INDEX
    # nlist: veriyi kac "kumeye" bolecegimiz. Genel kural: veri
    # sayisinin karekoku civari iyi bir baslangic. 5000'in karekoku
    # ~70, biz yuvarlak bir sayi olan 50 kullanacagiz.
    #
    # IVF'nin, kullanilmadan once "egitilmesi" (train) gerekir -
    # bu, veriye bakarak kumelerin nasil olusturulacagina karar verme
    # islemidir.
    # ------------------------------------------------------------
    nlist = 50
    quantizer = faiss.IndexFlatIP(boyut)  # IVF'nin ic mekanizmasi icin bir "olcum" index'i
    ivf_index = faiss.IndexIVFFlat(quantizer, boyut, nlist, faiss.METRIC_INNER_PRODUCT)
    ivf_index.train(embedding_matrisi)  # kumeleri olustur
    ivf_index.add(embedding_matrisi)  # vektorleri ekle

    # ------------------------------------------------------------
    # 3. HNSW INDEX
    # M: her vektorun graf icinde kac komsuya baglanacagi. Yuksek M
    # = daha dogru ama daha fazla bellek/yavas kurulum. 32 yaygin
    # bir varsayilan deger.
    # ------------------------------------------------------------
    M = 32
    hnsw_index = faiss.IndexHNSWFlat(boyut, M, faiss.METRIC_INNER_PRODUCT)
    hnsw_index.add(embedding_matrisi)

    return {
        "flat": flat_index,
        "ivf": ivf_index,
        "hnsw": hnsw_index,
    }


def index_kaydet(index_sozlugu):
    """Her index'i ayri bir dosyaya diske yazar."""
    for isim, index in index_sozlugu.items():
        faiss.write_index(index, f"index/{isim}_index.faiss")
    print("Tum index'ler diske kaydedildi (index/ klasorunde).")


if __name__ == "__main__":
    print("Embedding'ler yukleniyor...")
    embedding_matrisi = np.load(EMBEDDING_DOSYASI)
    print(f"Yuklendi: {embedding_matrisi.shape}")

    print("\n3 farkli index kuruluyor (Flat, IVF, HNSW)...")
    baslangic = time.time()
    index_sozlugu = index_kur(embedding_matrisi)
    print(f"Kurulum suresi: {time.time() - baslangic:.2f} saniye")

    index_kaydet(index_sozlugu)

def _en_iyi_bm25_skoru(sorgu_metni):
    """
    Verilen sorgu icin BM25 arama sonuclarindaki EN YUKSEK skoru
    dondurur. Amac: CLIP skoru "gri bolge"de (belirsiz) kaldiginda,
    BM25'in bu sorgu icin anlamli bir keyword eslesmesi bulup
    bulamadigina bakmak.

    bm25_ara() imzasi (hybrid_search.py'deki _bm25_ile_ara()'dan
    kopyalandi): bm25_ara(bm25, dosya_yollari, caption_listesi,
    sorgu_metni, k) ve donus degeri {"dosya":..., "caption":...,
    "skor":...} seklinde sozluklerden olusan, skora gore SIRALI
    bir liste.
    """
    sonuclar = bm25_ara(_bm25, _bm25_dosya_yollari, _bm25_caption_listesi, sorgu_metni, k=1)
    if not sonuclar:
        return 0.0
    return sonuclar[0]["skor"]

# ============================================================
# Bu dosya, Unsplash ve Openverse API'lerini kullanarak INTERNETTEN
# gorsel arar. Yerel veri setimizde (5.000 COCO gorseli) yeterli
# eslesme bulunamadiginda devreye giren "YEDEK PLAN" (fallback)
# katmanidir.
# ============================================================

import os
import requests
from dotenv import load_dotenv

load_dotenv()

UNSPLASH_ACCESS_KEY = os.getenv("UNSPLASH_ACCESS_KEY")
UNSPLASH_ARAMA_URL = "https://api.unsplash.com/search/photos"
OPENVERSE_ARAMA_URL = "https://api.openverse.org/v1/images/"
OPENVERSE_BASLIK = {"User-Agent": "multimodal-arama-motoru-ogrenci-projesi"}


def unsplash_ile_ara(sorgu_metni, k=5):
    """Unsplash API'sinden gorsel adaylari getirir."""
    if not UNSPLASH_ACCESS_KEY:
        print("UYARI: UNSPLASH_ACCESS_KEY bulunamadi (.env dosyasini kontrol et).")
        return []

    parametreler = {
        "query": sorgu_metni,
        "per_page": k,
        "client_id": UNSPLASH_ACCESS_KEY,
    }

    try:
        cevap = requests.get(UNSPLASH_ARAMA_URL, params=parametreler, timeout=10)
        cevap.raise_for_status()
        veri = cevap.json()

        sonuclar = []
        for gorsel in veri.get("results", []):
            sonuclar.append({
                "url": gorsel["urls"]["regular"],
                "fotografci": gorsel["user"]["name"],
                "kaynak": "unsplash",
            })
        return sonuclar

    except requests.exceptions.RequestException as hata:
        print(f"Unsplash arama hatasi: {hata}")
        return []


def openverse_ile_ara(sorgu_metni, k=5):
    """Openverse API'sinden (API anahtari gerektirmez) ek gorsel adaylari getirir."""
    parametreler = {"q": sorgu_metni, "page_size": k}
    try:
        cevap = requests.get(
            OPENVERSE_ARAMA_URL, params=parametreler, headers=OPENVERSE_BASLIK, timeout=15
        )
        if cevap.status_code != 200:
            return []

        sonuclar = []
        for s in cevap.json().get("results", []):
            gorsel_url = s.get("thumbnail") or s.get("url")
            if not gorsel_url:
                continue
            sonuclar.append({
                "url": gorsel_url,
                "fotografci": s.get("creator") or "Anonim",
                "kaynak": "openverse",
            })
        return sonuclar
    except Exception as hata:
        print(f"Openverse arama hatasi: {hata}")
        return []


def harici_kaynaklarda_ara(sorgu_metni, k=8):
    """
    Hem Unsplash hem Openverse uzerinde arama yaparak aday havuzunu
    birlestirir. Boylece tek bir stok fotograf sitesinin sinirlarina
    takilmayiz.
    """
    unsplash_adaylari = unsplash_ile_ara(sorgu_metni, k=k)
    openverse_adaylari = openverse_ile_ara(sorgu_metni, k=max(4, k // 2))
    return unsplash_adaylari + openverse_adaylari


if __name__ == "__main__":
    test_sorgusu = "dog wearing wings"
    sonuclar = harici_kaynaklarda_ara(test_sorgusu, k=4)
    for i, s in enumerate(sonuclar, 1):
        print(f"{i}. [{s['kaynak']}] {s['url']} ({s['fotografci']})")

    sorgu_vektoru = encode_text(sorgu_metni).reshape(1, -1).astype("float32")
    _, I = _hnsw_index.search(sorgu_vektoru, k)
    return [_clip_dosya_yollari[indeks] for indeks in I[0]]


def _bm25_ile_ara(sorgu_metni, k=20):
    sonuclar = bm25_ara(_bm25, _bm25_dosya_yollari, _bm25_caption_listesi, sorgu_metni, k=k)
    return [sonuc["dosya"] for sonuc in sonuclar]


def hibrit_ara(sorgu_metni, k=10):
    clip_sonuclari = _clip_ile_ara(sorgu_metni, k=20)
    bm25_sonuclari = _bm25_ile_ara(sorgu_metni, k=20)
    birlesik_siralama = reciprocal_rank_fusion([clip_sonuclari, bm25_sonuclari])
    return birlesik_siralama[:k]


def _en_iyi_clip_skoru(sorgu_metni):
    sorgu_vektoru = encode_text(sorgu_metni).reshape(1, -1).astype("float32")
    D, _ = _hnsw_index.search(sorgu_vektoru, 1)
    return float(D[0][0])

def _ai_ile_eksikleri_uret(sorgu_metni, adet):
    """
    ONEMLI HIZLANDIRMA: Istenen adet kadar AI gorselini SIRAYLA degil,
    ThreadPoolExecutor ile AYNI ANDA (paralel) uretir. Boylece 4 gorsel
    uretimi 4 kat surmez, tek gorsel suresinde (~10-15 sn) biter.
    """
    print(f"[akilli_ara] {adet} adet AI gorseli PARALEL olarak uretiliyor...")
    gorevler = [(sorgu_metni, i) for i in range(adet)]

    with ThreadPoolExecutor(max_workers=min(adet, 4)) as havuz:
        sonuclar = list(havuz.map(_tek_ai_gorsel_uret_gorevi, gorevler))

    uretilenler = []
    son_prompt = None
    for s in sonuclar:
        if s is not None:
            son_prompt = s.pop("prompt", None)
            uretilenler.append(s)

    return uretilenler, son_prompt


def akilli_ara(sorgu_metni, k=10, esik=0.29):
    from visual_judge import gorsel_hakem_onayla

    en_iyi_skor = _en_iyi_clip_skoru(sorgu_metni)
    print(f"[akilli_ara] '{sorgu_metni}' icin en iyi yerel CLIP skoru: {en_iyi_skor:.4f} (esik: {esik})")

    # --- KATMAN 1: YEREL ARAMA + VLM HAKEM ---
    if en_iyi_skor >= esik:
        yerel_adaylar = hibrit_ara(sorgu_metni, k=min(k + 2, 6))
        onaylanan_yerel = []
        print(f"[akilli_ara] Yerel adaylar VLM Hakem ile dogrulaniyor...")
        for dosya_yolu, rrf_skoru in yerel_adaylar:
            if gorsel_hakem_onayla(dosya_yolu, sorgu_metni):
                onaylanan_yerel.append((dosya_yolu, rrf_skoru))
                if len(onaylanan_yerel) >= k:
                    break

        if len(onaylanan_yerel) >= k or (len(onaylanan_yerel) > 0 and en_iyi_skor >= 0.32):
            return {
                "kaynak": "yerel",
                "en_iyi_skor": en_iyi_skor,
                "sonuclar": onaylanan_yerel[:k],
            }
        print("[akilli_ara] Yerel adaylar VLM Hakem'i gecemedi - HARICI aramaya geciliyor...")

    # --- KATMAN 2: HARICI ARAMA + PARALEL INDIRME + CLIP + VLM HAKEM ---
    from external_search import unsplash_ile_ara, openverse_ile_ara
    from prompt_engineer import arama_sorgulari_uret

    arama_sorgulari = arama_sorgulari_uret(sorgu_metni)
    print(f"[akilli_ara] Harici arama varyasyonlari: {arama_sorgulari}")

    harici_adaylar = []
    gorulen_temel_urller = set()

    # Maksimum 2 varyasyon + Openverse ile aday havuzunu makul boyutta (maks ~12 aday) tut
    for alt_sorgu in arama_sorgulari[:2]:
        for aday in unsplash_ile_ara(alt_sorgu, k=5):
            temel_url = aday["url"].split("?")[0]
            if temel_url not in gorulen_temel_urller:
                gorulen_temel_urller.add(temel_url)
                harici_adaylar.append(aday)

    for aday in openverse_ile_ara(arama_sorgulari[0], k=3):
        temel_url = aday["url"].split("?")[0]
        if temel_url not in gorulen_temel_urller:
            gorulen_temel_urller.add(temel_url)
            harici_adaylar.append(aday)

    onaylanan_harici = []
    en_iyi_harici_skor = 0.0

    if harici_adaylar:
        print(f"[akilli_ara] {len(harici_adaylar)} aday paralel indiriliyor ve CLIP ile puanlaniyor...")
        sorgu_vektoru = encode_text(sorgu_metni)
        indirilen_adaylar = []

        with ThreadPoolExecutor(max_workers=10) as havuz:
            indirilen_ciftler = list(havuz.map(_aday_indir_gorevi, harici_adaylar))

        for aday, gecici_yol in indirilen_ciftler:
            if not gecici_yol:
                continue
            try:
                gorsel_vektoru = encode_image(gecici_yol)
                skor = float(np.dot(gorsel_vektoru, sorgu_vektoru))
                en_iyi_harici_skor = max(en_iyi_harici_skor, skor)
                print(f"  - [{aday['kaynak']}] {aday['url'][:48]}... CLIP skoru: {skor:.4f}")

                if skor >= HARICI_ESIK:
                    indirilen_adaylar.append((aday, skor, gecici_yol))
                else:
                    os.remove(gecici_yol)
            except Exception:
                if os.path.exists(gecici_yol):
                    os.remove(gecici_yol)

        indirilen_adaylar.sort(key=lambda x: x[1], reverse=True)

        if indirilen_adaylar:
            # Sadece en yuksek skorlu (k + 1) adayi VLM Hakem'e sor (hiz icin)
            maks_vlm_adayi = k + 1
            print(f"[akilli_ara] En iyi {min(len(indirilen_adaylar), maks_vlm_adayi)} aday VLM Hakem ile denetleniyor...")
            for idx, (aday, skor, gecici_yol) in enumerate(indirilen_adaylar):
                if idx < maks_vlm_adayi and len(onaylanan_harici) < k:
                    if gorsel_hakem_onayla(gecici_yol, sorgu_metni):
                        onaylanan_harici.append(aday)
                if os.path.exists(gecici_yol):
                    os.remove(gecici_yol)

        if len(onaylanan_harici) >= k:
            return {
                "kaynak": "harici",
                "en_iyi_skor": en_iyi_skor,
                "harici_clip_skoru": en_iyi_harici_skor,
                "sonuclar": onaylanan_harici[:k],
            }

        if 0 < len(onaylanan_harici) < k:
            eksik_adet = k - len(onaylanan_harici)
            print(
                f"[akilli_ara] Web'de {len(onaylanan_harici)}/{k} dogru gorsel onaylandi. "
                f"Eksik {eksik_adet} gorsel AI ile PARALEL tamamlanacak..."
            )
            uretilen_ekler, son_prompt = _ai_ile_eksikleri_uret(sorgu_metni, eksik_adet)
            return {
                "kaynak": "harici",
                "kismi_uretim": True,
                "en_iyi_skor": en_iyi_skor,
                "harici_clip_skoru": en_iyi_harici_skor,
                "zenginlestirilmis_prompt": son_prompt,
                "sonuclar": onaylanan_harici + uretilen_ekler,
            }

        print("[akilli_ara] Harici adaylarin HICBIRI VLM Hakem'i gecemedi - TAM URETIME geciliyor...")
    else:
        print("[akilli_ara] Harici kaynaklarda hic sonuc bulunamadi - TAM URETIME geciliyor...")

    # --- KATMAN 3: TAM AI URETIM (PARALEL) ---
    uretilen_sonuclar, son_kullanilan_prompt = _ai_ile_eksikleri_uret(sorgu_metni, k)
    return {
        "kaynak": "uretilen",
        "en_iyi_skor": en_iyi_skor,
        "zenginlestirilmis_prompt": son_kullanilan_prompt,
        "sonuclar": uretilen_sonuclar,
    }

import os
import io
import random
import urllib.parse
import requests
from PIL import Image
from huggingface_hub import InferenceClient
from dotenv import load_dotenv

load_dotenv()
HF_TOKEN = os.getenv("HF_TOKEN")

FLUX_MODELI = "black-forest-labs/FLUX.1-schnell"

_hf_client = None
_hf_kredi_bitti = False


def _hf_client_olustur():
    global _hf_client
    if _hf_client is None:
        if not HF_TOKEN:
            raise RuntimeError("HF_TOKEN bulunamadi.")
        _hf_client = InferenceClient(token=HF_TOKEN, timeout=15)
    return _hf_client


def _flux_hf_ile_uret(prompt):
    global _hf_kredi_bitti
    if _hf_kredi_bitti:
        raise RuntimeError("HF kredisi tukenmis durumda.")

    client = _hf_client_olustur()
    rastgele_seed = random.randint(0, 2**32 - 1)
    print(f"[image_generation] HF FLUX.1-schnell deneniyor (seed={rastgele_seed})...")
    try:
        return client.text_to_image(prompt, model=FLUX_MODELI, seed=rastgele_seed)
    except Exception as hata:
        # Herhangi bir kredi/odeme veya API hatasinda bu oturumda HF'yi bir daha deneme
        _hf_kredi_bitti = True
        raise hata


def _pollinations_ile_uret(prompt, model_adi="flux", timeout_sn=18):
    """
    Pollinations bulut API'si ile hizli gorsel uretir.
    enhance=false sayesinde prompt bozulmaz, kisa timeout sayesinde sistem asili kalmaz.
    """
    temiz_prompt = " ".join(prompt.replace("/", " ").replace("\n", " ").split())
    kodlanmis_prompt = urllib.parse.quote(temiz_prompt, safe="")
    rastgele_seed = random.randint(1, 99999999)
    url = (
        f"https://image.pollinations.ai/prompt/{kodlanmis_prompt}"
        f"?width=768&height=768&seed={rastgele_seed}&model={model_adi}&nologo=true&enhance=false"
    )
    basliklar = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"}
    print(f"[image_generation] Bulut ({model_adi}) ile uretiliyor (seed={rastgele_seed})...")
    cevap = requests.get(url, headers=basliklar, timeout=timeout_sn)
    cevap.raise_for_status()
    return Image.open(io.BytesIO(cevap.content)).convert("RGB")


def gorsel_uret(prompt, cikti_klasoru="data/uretilen_gorseller", dosya_adi=None):
    os.makedirs(cikti_klasoru, exist_ok=True)

    kullanilan_model = "FLUX.1-schnell (HF)"
    try:
        gorsel = _flux_hf_ile_uret(prompt)
    except Exception:
        try:
            kullanilan_model = "FLUX.1 (Bulut)"
            gorsel = _pollinations_ile_uret(prompt, model_adi="flux", timeout_sn=18)
        except Exception as flux_hata:
            print(f"[image_generation] Bulut FLUX gecikti ({flux_hata}) -> Hizli Bulut Turbo'ya geciliyor...")
            kullanilan_model = "SDXL-Turbo (Bulut)"
            gorsel = _pollinations_ile_uret(prompt, model_adi="turbo", timeout_sn=12)

    if dosya_adi is None:
        dosya_adi = f"uretilen_{abs(hash(prompt)) % 100000}_{random.randint(1000, 9999)}.png"

    yol = os.path.join(cikti_klasoru, dosya_adi)
    gorsel.save(yol)
    print(f"[image_generation] Kaydedildi ({kullanilan_model}): {yol}")

    return yol, kullanilan_model

import os
from groq import Groq
from dotenv import load_dotenv

load_dotenv()
GROQ_API_KEY = os.getenv("GROQ_API_KEY")
GROQ_MODEL = "openai/gpt-oss-20b"

SABLON_ONEK = "A clear, photorealistic close-up or medium shot of "
SABLON_SONEK = ", sharp focus on the main subject, natural lighting, high quality, 4k"

_groq_client = None


def _client_olustur():
    global _groq_client
    if _groq_client is None:
        if not GROQ_API_KEY:
            raise RuntimeError("GROQ_API_KEY bulunamadi (.env dosyasini kontrol et).")
        _groq_client = Groq(api_key=GROQ_API_KEY)
    return _groq_client


def _groq_ile_sor(talimat, temperature=0.6):
    try:
        client = _client_olustur()
        cevap = client.chat.completions.create(
            model=GROQ_MODEL,
            messages=[{"role": "user", "content": talimat}],
            temperature=temperature,
        )
        sonuc = (cevap.choices[0].message.content or "").strip().strip('"').strip()
        sonuc = sonuc.replace("\u2011", "-")
        return sonuc
    except Exception as hata:
        print(f"Groq cagrisi basarisiz oldu ({hata}).")
        return None


def zenginlestir_prompt(kullanici_sorgusu, varyasyon_no=0):
    """
    Kullanicinin sorgusunu AI gorsel uretim modeli (FLUX) icin zenginlestirir.
    ONEMLI: 'Wide establishing shot' gibi ana ozneyi manzarada kaybettiren
    ve 'kanatli kopek' yerine 'kartal' cizilmesine yol acan acilar kaldirildi.
    """
    varyasyon_ipuclari = [
        "Framing: clear medium shot at eye level, studio lighting.",
        "Framing: close-up portrait shot in a natural outdoor setting, soft sunlight.",
        "Framing: full-body shot standing clearly in the center of the frame, cinematic lighting.",
        "Framing: three-quarter angle shot, warm golden hour lighting, shallow depth of field.",
    ]
    ipucu = varyasyon_ipuclari[varyasyon_no % len(varyasyon_ipuclari)]

    talimat = (
        "Rewrite the following user query into a clear, photorealistic image generation prompt.\n\n"
        "CRITICAL RULES:\n"
        "1. The FIRST sentence MUST explicitly state the main subject and all requested objects/colors "
        f"from '{kullanici_sorgusu}'. Never replace or omit the main subject.\n"
        "2. If the query combines an animal with an unusual attribute (e.g. 'a winged dog', 'a cat with a mustache'), "
        "describe the actual animal clearly first (e.g. 'A real photorealistic dog with a clear canine face and four legs, "
        "wearing realistic angel/feathered wings on its back'). NEVER turn the animal into a bird or eagle.\n"
        "3. Keep the subject large and clearly visible in the center. Do NOT write poetic metaphors or distant landscapes.\n"
        f"4. {ipucu}\n"
        "5. Keep the ENTIRE response under 45 words. Reply with ONLY the prompt, no quotes, no slashes."
        f"\n\nUser query: {kullanici_sorgusu}"
    )

    sonuc = _groq_ile_sor(talimat, temperature=0.5)
    if sonuc and len(sonuc) > 15:
        return sonuc

    return f"{SABLON_ONEK}{kullanici_sorgusu}{SABLON_SONEK}"


def arama_sorgusu_zenginlestir(kullanici_sorgusu, temperature=0.4):

def arama_sorgulari_uret(kullanici_sorgusu):
    """
    Tek bir arama terimiyle sinirli kalmamak icin 3 farkli stok fotograf
    arama sorgusu uretir (orn. 'dog wearing wings', 'dog angel wings costume',
    'dog bat wings'). Boylece Unsplash'te daha fazla gercek fotograf yakalanir.
    """
    talimat = (
        "Generate 3 short, distinct stock-photo search queries (each 2 to 5 words) "
        "to find real photographs matching the user phrase.\n\n"
        "RULES:\n"
        "1. If the phrase gives an animal a feature it cannot naturally have (e.g. wings on a dog, horns on a horse, "
        "mustache on a cat), generate variations for a REAL photoshoot with costumes/props:\n"
        "   Example for 'a winged dog':\n"
        "   dog wearing wings\n"
        "   dog angel wings costume\n"
        "   dog halloween wings\n"
        "2. If the phrase is already a literal scene (e.g. 'a blue car in front of a yellow house'), "
        "provide 3 concise keyword variations keeping the key nouns and colors.\n"
        "3. Reply with ONLY the 3 queries, one per line, no numbering, no bullets, no quotes.\n\n"
        f"Phrase: {kullanici_sorgusu}"
    )

    sonuc = _groq_ile_sor(talimat, temperature=0.4)
    if sonuc:
        satirlar = [
            s.strip().strip("-*1234567890. \"'")
            for s in sonuc.splitlines()
            if len(s.strip()) > 2
        ]
        # Tekrarlari kaldirirken sirayi koru
        benzersiz = []
        for s in satirlar:
            if s.lower() not in [b.lower() for b in benzersiz]:
                benzersiz.append(s)
        if benzersiz:
            return benzersiz[:3]

    return [kullanici_sorgusu]

# ============================================================
# Bu dosya, Reciprocal Rank Fusion (RRF) algoritmasini icerir.
#
# PROBLEM: Elimizde IKI farkli arama sonucu var:
#   1. CLIP (semantic) aramasinin sonuc siralamasi
#   2. BM25 (keyword) aramasinin sonuc siralamasi
# Bu ikisinin SKORLARI birbiriyle KARSILASTIRILAMAZ - CLIP'in
# skorlari 0-1 arasi cosine similarity, BM25'inkiler ise 0'dan
# yukari (10, 20 gibi) sinirsiz sayilar olabilir. Ikisini dogrudan
# toplayip "ortalama" almak ANLAMSIZ olur - farkli olcum birimleri.
#
# COZUM: RRF, SKORLARI DEGIL, SIRALARI (rank) kullanir. Yani "bu
# gorsel CLIP'te 3. sirada, BM25'te 7. sirada" gibi bilgiyi kullanir -
# skorlarin BUYUKLUGU onemli degil, sadece SIRASI onemli. Bu, RRF'yi
# hem basit hem de "adil" (iki farkli sistemi taraf tutmadan
# birlestiren) bir yontem yapar.
#
# FORMUL: Her gorsel icin, HER LISTEDE bulundugu sira numarasina
# gore bir "RRF skoru" hesaplanir:
#
#     RRF_skoru = sum( 1 / (k + sira) )
#
# Bu toplam, gorselin GECTIGI HER LISTE icin ayri ayri hesaplanip
# TOPLANIR. Yani bir gorsel hem CLIP'te hem BM25'te ust siralarda
# ciktiysa, iki kere "puan" alir ve toplam RRF skoru yuksek cikar -
# bu da onun NIHAI siralamada one cikmasini saglar.
#
# k=60 SABITI NEREDEN GELIYOR? Bu, RRF'nin orijinal akademik
# makalesinde (Cormack, Clarke, Buettcher 2009) onerilen ve
# pratikte iyi sonuc verdigi gozlemlenen standart bir deger.
# k'nin gorevi: siralamanin BASINDAKI (1., 2., 3. sira) farklarin
# etkisini biraz "yumusatmak" - k olmasa 1. sira ile 2. sira arasi
# skor farki cok BUYUK olurdu (1/1=1.0 vs 1/2=0.5, yani %50 fark),
# k=60 eklenince bu fark kuculuyor (1/61=0.0164 vs 1/62=0.0161,
# yani sadece %2 fark) - boylece siralamanin ALT kisimlarindaki
# kucuk farklar da anlamli katki yapabiliyor.
# ============================================================


def reciprocal_rank_fusion(sonuc_listeleri, k=60, agirliklar=None):
    """
    Birden fazla arama sonucu listesini RRF ile tek bir siralamada
    birlestirir.

    agirliklar: (YENI, istege bagli) her listenin katkisini carpan
    agirlik listesi, sonuc_listeleri ile AYNI uzunlukta olmali.
    None verilirse tum listeler esit agirlikli (1.0) sayilir; bu,
    eski davranisla BIREBIR aynidir.

    Formul: RRF_skoru = sum( agirlik / (k + sira) )
    """
    # Agirlik verilmediyse her liste icin 1.0 kullan (eski davranis)
    if agirliklar is None:
        agirliklar = [1.0] * len(sonuc_listeleri)
    # Agirlik sayisi liste sayisiyla uyusmuyorsa sessizce yanlis hesaplamak
    # yerine hemen hata ver
    if len(agirliklar) != len(sonuc_listeleri):
        raise ValueError("agirliklar, sonuc_listeleri ile ayni uzunlukta olmali")

    # Her kimligin toplam RRF skorunu bu sozlukte biriktiriyoruz
    rrf_skorlari = {}

    # zip: her listeyi KENDI agirligiyla birlikte geziyoruz
    for liste, agirlik in zip(sonuc_listeleri, agirliklar):
        # Listedeki her elemani 1'den baslayan sira numarasiyla geziyoruz
        for sira, kimlik in enumerate(liste, start=1):
            # Katki payi: agirlik / (k + sira). Agirlik 1.0 ise eski formulle ayni
            katki = agirlik / (k + sira)
            # Onceki skora ekle (kimlik ilk kez goruluyorsa 0'dan basla)
            rrf_skorlari[kimlik] = rrf_skorlari.get(kimlik, 0) + katki

    # Skora gore buyukten kucuge sirala
    siralanmis_sonuclar = sorted(
        rrf_skorlari.items(), key=lambda x: x[1], reverse=True
    )

    return siralanmis_sonuclar


# Bu dosya dogrudan calistirildiginda, RRF'nin nasil calistigini
# GORECEKTIGIMIZ basit, elle hazirlanmis bir ornekle test ediyoruz -
# gercek CLIP/BM25 verisi kullanmadan, sadece MANTIGIN dogru
# calistigini dogruluyoruz.
if __name__ == "__main__":
    # Elle hazirlanmis, sahte (ornek) iki arama sonucu listesi.
    clip_sonucu = ["A", "B", "C", "D"]
    bm25_sonucu = ["C", "A", "E", "F"]

    print("CLIP sonucu (sirali):", clip_sonucu)
    print("BM25 sonucu (sirali):", bm25_sonucu)

    birlesik = reciprocal_rank_fusion([clip_sonucu, bm25_sonucu])

    print("\nRRF ile birlesmis nihai siralama:")
    for kimlik, skor in birlesik:
        print(f"  {kimlik}: {skor:.4f}")

    # BEKLENEN SONUC: "A" ve "C" ikisi de HER IKI listede de var
    # (A: CLIP'te 1., BM25'te 2. | C: CLIP'te 3., BM25'te 1.) -
    # bu yuzden A ve C'nin RRF skoru, sadece TEK bir listede olan
    # B, D, E, F'den DAHA YUKSEK cikmali. Bu, hibrit aramanin

# ============================================================
# Bu dosya, CLIP esigini gecen gorsellerin kullanici sorgusunu
# gercekten karsilayip karsilamadigini Groq VLM (qwen/qwen3.8-27b)

import os
import io
import time
import base64
from PIL import Image
from groq import Groq
from dotenv import load_dotenv

load_dotenv()
GROQ_API_KEY = os.getenv("GROQ_API_KEY")

VLM_MODEL = "qwen/qwen3.8-27b"

_vlm_client = None


def _client_olustur():
    global _vlm_client
    if _vlm_client is None:
        if not GROQ_API_KEY:
            raise RuntimeError("GROQ_API_KEY bulunamadi (.env dosyasini kontrol et).")
        _vlm_client = Groq(api_key=GROQ_API_KEY)
    return _vlm_client


def _gorseli_kucult_ve_kodla(gorsel_yolu, maks_boyut=384):
    """Gorseli 384x384 boyuta kuculterek token harcamasini ve gecikmeyi azaltir."""
    with Image.open(gorsel_yolu) as img:
        img = img.convert("RGB")
        img.thumbnail((maks_boyut, maks_boyut))
        tampon = io.BytesIO()
        img.save(tampon, format="JPEG", quality=80)
        return base64.b64encode(tampon.getvalue()).decode("utf-8")


def gorsel_hakem_onayla(gorsel_yolu, sorgu_metni):
    """
    Gorsel sorguyu tam olarak karsiliyorsa True, aksi halde False dondurur.
    """
    talimat = (
        "You are a strict visual relevance judge for an image search engine.\n"
        f"User query: '{sorgu_metni}'\n\n"
        "Does this image clearly and accurately show EVERY key element, attribute, "
        "color, and spatial relation in the user query?\n"
        "Strict Rules:\n"
        "1. Every requested object, color, and feature must be clearly visible.\n"
        "2. If a specific feature/costume is requested (e.g. wings, horns, mustache), "
        "it must actually be on that subject. A normal collar, bandana, scarf, or bow tie "
        "does NOT count as wings.\n"
        "3. Spatial relations (in front of, on top of, riding) and colors (e.g. blue car AND yellow house) "
        "must both be true at the same time.\n"
        "Answer with ONLY one word: yes or no."
    )

    client = _client_olustur()
    b64_gorsel = _gorseli_kucult_ve_kodla(gorsel_yolu)

    for deneme in range(2):
        try:
            cevap = client.chat.completions.create(
                model=VLM_MODEL,
                messages=[{
                    "role": "user",
                    "content": [
                        {"type": "text", "text": talimat},
                        {
                            "type": "image_url",
                            "image_url": {"url": f"data:image/jpeg;base64,{b64_gorsel}"},
                        },
                    ],
                }],
                temperature=0.0,
                max_completion_tokens=10,
                reasoning_effort="none",
            )

            yanit = (cevap.choices[0].message.content or "").strip().lower()
            onay = yanit.startswith("yes")
            print(f"    [VLM Hakem] Karar: {'ONAY (yes)' if onay else 'RED (no)'} (yanit: {yanit!r})")
            return onay

        except Exception as hata:
            if deneme == 0 and "429" in str(hata):
                print("    [VLM Hakem] Hiz siniri (429), 2 sn beklenip tekrar deneniyor...")
                time.sleep(2.0)
                continue
            # Hata durumunda onaysiz/alakasiz gorselin sizmasini onlemek icin False donuyoruz
            print(f"    [VLM Hakem UYARI] Cagri basarisiz ({hata}), guvenlik icin RED sayildi.")
            return False
    return False
